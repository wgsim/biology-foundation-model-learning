## 학습 목표
1. 검증 가능한 질문과, 주장할 수 있는 **최대 범위·말할 수 없는 것**을 결과를 보기 전에 적는다 (사전 등록).

## 1. 이 모듈이 다른 모듈과 다른 점
- **질문은 본인이 정하고 정답은 없다.** 평가는 결과의 크기·새로움이 아니라 *절차의 질*(루브릭)을 본다. "baseline이 이겼다"는 음성 결과도 만점이 될 수 있다.
- **설계를 먼저 쓴다.** 분할·지표·주 비교·결정 규칙은 결과 전에 고정하고, 바뀐 것은 날짜·이유와 함께 기록한다.
- **작게 시작한다.** 16~20시간에 끝나는 크기로 줄인다 — 한 데이터, 한 질문, 한 주 비교. 확장은 MVP가 끝난 뒤.
- **다운로드·설치는 사용자 승인 후에만.** 제안서에 파일·출처·크기를 적고 승인을 받는다. 이 모듈의 템플릿과 트랙 시작점은 이미 받아 둔 캐시만 쓴다.

## 3. 트랙 E: 논문 재현 프로토콜
Pineau et al.(arXiv:2003.12206 초록)은 재현성을 "같은 코드와 데이터(가능하면)로 논문에 보고된 것과 비슷한 결과를 얻는 것"으로 설명한다 — 이 프로토콜은 그 정의를 *주장 단위*로 좁힌다.
1. **논문 고르기** ([논문 노트 템플릿](../00_orientation/paper_note_template.md)과 3-pass 읽기로): ① 핵심 주장이 한 문장, ② 코드·데이터·가중치가 공개되어 있고 **라이선스를 확인**했다, ③ 컴퓨팅이 16~20시간 안에 들어간다, ④ 재현할 **주장 단위**(표 한 칸 또는 그림 하나)를 특정할 수 있다. [reading_list](../resources/reading_list.md)의 ✅ 논문에서 고르되 코드 공개 여부는 직접 확인한다.
2. **재현 수준을 정한다**: **L1 숫자 재현**(공개 코드·가중치로 해당 수치가 허용 오차 안), **L2 재구현**(핵심 파이프라인을 직접 구현해 L1과 비교), **L3 변형 검증**(분할·baseline·ablation을 바꿔 주장이 유지되는지). 권장: L1 + L3 하나.
3. **허용 오차를 재현 전에 정의한다.** 논문이 구간을 주지 않으면 시드 변동으로 정한다 ("±0.02" 같은 값을 결과를 본 뒤에 고르지 않는다).
4. **편차 기록(deviation log)**: 데이터 버전, 전처리, 환경, 시드, 논문에 없던 세부를 날짜와 함께.
5. **재현이 안 될 때**: 원인 후보(데이터 버전, 전처리, 평가 코드, 누출 가능성, 시드)를 하나씩 점검하고, 저자 코드와 비교한다. "재현 실패"는 유효한 결과이지만 **원인을 확인하지 못했으면 그렇게 쓴다** — 논문이 틀렸다고 단정하지 않는다.
6. 보고서는 [report_template](templates/report_template.md)를 쓰되 §1에 재현 수준과 허용 오차, §5에 "논문의 주장과 내가 확인한 것의 차이"를 둔다.

## 5. 템플릿 노트북이 보여 주는 것 (데모 결과)
ProteinGym `DN7A_SACS2_Tsuboyama_2023_1JIC`(길이 55, 단일 치환 1,008개), ESM-2 8M, 시드 5개, 약 20초. **데모의 결과이며 어떤 일반화도 아니다.**

| | random | position-block (10) |
|---|---|---|
| test 위치가 train에도 있는 비율 / 같은 wt→mt 쌍이 train에 있는 비율 / train까지 위치 거리 중앙값 | 1.00 / 0.88 / 0 | 0.00 / 0.77 / 4.6 |
| B1 (aa 원-핫 + BLOSUM) | 0.69 | 0.59 |
| B2 (B1 + 위치 원-핫) | 0.80 | 0.57 |
| probe (동결 ESM-2 8M) | 0.81 | 0.50 |
| probe-randinit (무작위 초기화) | 0.64 | 0.44 |
| probe-shuffled (음성 대조) | −0.02 (SD 0.09) | −0.08 (SD 0.19, 시드 하나의 \|ρ\| 최대 0.29) |

| 짝지은 차이 Δ [그룹 부트스트랩 95%] (이긴 시드) | random | position-block |
|---|---|---|
| probe − B2 | +0.010 [−0.012, +0.026] (4/5) | **−0.065 [−0.086, +0.034] (0/5)** ← 사전 지정 주 비교 |
| probe − B1 | +0.112 [+0.075, +0.154] (5/5) | −0.083 [−0.107, +0.004] (0/5) |
| probe − probe-randinit | +0.167 [+0.129, +0.204] (5/5) | +0.063 [+0.011, +0.135] (4/5) |

사전 지정한 결정 규칙("구간이 0을 포함하지 않고 양수이면 지지")에 따라 판정은 **'지지되지 않음'**이다. 블록 크기 민감도(3 / 5 / 10): Δ(probe−B2) = −0.064 / −0.013 / −0.065. 읽는 법:
- random 분할의 probe는 B2와 같고(+0.010) B1보다 높다. 그러나 위치가 train에 100% 들어 있어, 이 점수는 위치 효과를 쓰는 baseline과 구분되지 않는다. position-block에서는 probe가 B1·B2보다 낮다.
- 사전학습의 기여(probe − 무작위 초기화)는 두 분할 모두 양수지만 position-block에서 작다(+0.063).
- 음성 대조의 시드 평균은 0 근처지만 position-block에서는 test가 소수 위치에 몰려(유효 표본 수 ≈ 위치 수) 시드 하나의 |ρ|가 0.3까지 갔다. **한 시드의 값만으로 누출을 판단하지 않고 평균과 변동을 본다.**
- 구간은 고정된 예측에 대한 조건부 구간이다. 시드 5개 · 한 assay · 한 모델 크기 · Ridge만.

## 6. 평가 루브릭과 점검표

## 7. 독립 검토 받기
모듈 04~06에서 한 방식을 일반화했다: 읽기 전용으로 두 모델 이상에 보내고([프롬프트 템플릿](templates/review_prompt_template.txt)), 지적을 **하나씩 코드·출력으로 검증**한다. 이 과정에서 검토는 매번 실제 버그를 찾았지만(예: 서열 중복이 분할에 걸림, 표준화가 내부 CV에 섞임, PCA 표본이 길이순 앞부분) 일부 지적은 오해였다(예: 전체 데이터로 상수 열을 빼는 것). 검토자에게 **확인하지 못한 것과 중간에 틀렸다가 고친 것**을 알려 주면 거짓 양성이 줄어든다. 수용·기각 근거를 표로 남기고(보고서 부록), 고친 뒤에는 노트북을 처음부터 다시 실행한다.

**Q2.** "층 4, 8, 12를 비교해 test Spearman이 가장 높은 층 8을 사용했다. 설정은 사전에 고정했다."
<details><summary>답</summary>
test 결과로 층을 고르고 "사전 고정"이라고 쓴 것은 루브릭의 red flag다(차원 2·5 상한 1점). 사전 고정이었다면 층을 미리 정하고 나머지는 *민감도*로 보고하고, 선택이 필요하면 학습 안 검증 분할(바깥과 같은 방식)로 골라야 한다. 모듈 04의 층 선택(0.18 차이)과 모듈 06의 LoRA 민감도가 같은 문제를 보여 준다.
</details>

**Q3.** "scaffold 분할을 썼으므로 train–test 누출은 없다."
<details><summary>답</summary>
분할 이름은 누출의 부재를 보장하지 않는다. 모듈 05에서 scaffold 분할에서도 Lipophilicity test의 26%가 train에 Tanimoto ≥ 0.7인 분자를 가졌다(최근접 유사도 중앙값 0.57). 분할 후 test→train 유사도를 측정해 보고하고, 막지 못한 경로를 더 엄격한 분할이나 층화로 점검한다.
</details>

**Q4.** "BBBP에서 모든 폴드의 예측을 합쳐 AUROC를 구했다. 층 0의 `<s>` 표현은 0.46이어서 우연보다 약간 나쁘다."
<details><summary>답</summary>
폴드마다 다른 모델의 점수 척도를 하나로 섞으면 상수 예측도 폴드별 평균 예측의 차이 때문에 0.5에서 벗어난다. 폴드별 AUROC를 구해 평균하면 이 상수 표현은 정확히 0.500이다(모듈 05). 같은 이유로 풀링한 지표는 폴드 간 보정 차이에 민감하다.
</details>

**Q5.** "시드 3개 평균에서 LoRA(0.41)가 probe(0.56)보다 낮았으므로 LoRA는 이 과제에 쓸모가 없다."
<details><summary>답</summary>
고정된 하나의 설정(r=8, lr 1e-3, 5 에폭)과 시드 3개, 8M 모델, 검증 기반 선택 없음의 결과일 뿐이다. 같은 노트북의 민감도에서 LoRA는 설정에 따라 0.29~0.50으로 흔들렸고 35M·시드 2개에서는 순서가 달랐다(모듈 06). "이 고정 설정에서는 이기지 못했다"가 데이터가 지지하는 서술이다.
</details>

**Q6.** "검토 모델이 지적한 12개 항목을 모두 반영했다."
<details><summary>답</summary>
지적을 검증 없이 모두 수용한 것은 루브릭의 red flag다. 검토자는 실제 버그를 찾지만 오해도 한다(모듈 06: 전체 데이터로 상수 열을 빼는 것은 어떤 예측도 바꾸지 않아 누출이 아니다). 각 지적을 코드·출력으로 확인해 수용·기각 근거를 표로 남기고, 고친 뒤 처음부터 재실행해 실행본과 제출 코드가 같은지 확인해야 한다.
</details>

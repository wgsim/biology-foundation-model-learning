# 트랙 B·C·D 시험 실행 기록

> **이 기록의 성격**: 트랙 A는 [템플릿 노트북](../../templates/capstone_notebook_template.ipynb)이 직접 실행되지만 B~D는 시작점만 가리키고 있었다. 이 기록은 **과정을 만든 쪽이 각 트랙의 MVP(사전 지정 비교 하나)를 골라 템플릿 구조(사전 등록 → 출처 → 데이터 점검 → 단위·누출 → baseline → 평가 → 대조 → 민감도)로 옮겨 실제로 돌려 본 것**이다.
> - **학습자 파일럿이 아니다.** 학습자가 걸릴 시간이나 막히는 곳은 재지 않았다.
> - **실제 사전 등록이 아니다.** 설계와 결과를 같은 시기에 만들었고 결정 규칙도 결과를 보기 전에 정했다고 증명할 수 없다. 형식을 보여 주려는 [트랙 A 예시](../example_track_A_proposal_and_report.md)와 같은 위치다.
> - 각 비교는 **한 번의 실행**이다. 아래 결과를 "DNA LM / 단일세포 FM / 화학 LM은 …하다"로 일반화하지 말 것.
> - Codex·agy 교차 리뷰를 받았다(맨 아래 "교차 리뷰" 절). 지적은 코드로 확인해 반영했고, 반영하지 않은 것은 이유를 적었다.
> - 이 기록이 "미실시"로 남긴 질문의 나머지 절반은 [second_halves.md](second_halves.md)에서 이어서 돌렸다(2026-11-09).

실행 환경: Mac(CPU/MPS), 저장소 `.venv`, 새 다운로드 없음(모듈 03·04·05가 받아 둔 캐시만 사용). 코드는 이 폴더의 스크립트 3개이며 저장소 루트에서 실행한다 (`HF_HOME=$PWD/.cache/hf HF_HUB_OFFLINE=1 .venv/bin/python -I <스크립트>`). 실행 기록(`provenance.json`)은 `.cache/capstone_runs/<RUN_NAME>/`(git 제외)에 쓴다.

## 트랙 B — TraitGym에서 NT LLR vs 보존 점수
- **설정(고정)**: TraitGym `mendelian_traits_matched_9`(변이 3,380, 양성 338, 양성 1개당 매칭된 대조 9개 = `match_group` 338개, 염색체 19개). 지표 AUPRC. 점수의 부호는 데이터를 보기 전에 규정(LLR −, 보존 +). Δ = AUPRC(모델) − AUPRC(baseline). 결정 규칙: 염색체별 Δ(양성 ≥ 5인 14개)의 평균 ≥ 0.02, Δ > 0인 염색체 ≥ 10/14, `match_group` 단위 짝지은 부트스트랩(500회) 95% 구간 하한 > 0 → '지지'. 점수별 순열 귀무분포는 1,000회.
- **데이터 점검(assert)**: 점수 파일과 변이표의 행 수 일치, NaN 없음, 그룹당 양성 정확히 1개, 그룹이 한 염색체 안에 있음, 변이 중복 없음. 모두 통과.
- **AUPRC** (순열 p는 *점수마다* 그 점수의 값을 `match_group` 안에서 섞은 1,000회의 풀링 AUPRC 분포와 비교한다. 귀무 평균은 0.100~0.102, 95% 분위수는 0.103~0.112; p의 최솟값은 0.001):

| 점수 | AUPRC | 순열 p |
|---|---|---|
| NT LLR (TraitGym 제공) | 0.103 | 0.445 |
| Evo2-7B LLR | 0.381 | 0.001 |
| phyloP-241m | 0.673 | 0.001 |
| phyloP-100v / phastCons-43p | 0.653 / 0.497 | 0.001 / 0.001 |
| TSS 거리만 (매칭 변수) | 0.115 | 0.001 |

- **주 비교** NT LLR − phyloP-241m: 풀링 Δ −0.571 [−0.618, −0.519], 염색체 평균 Δ −0.561, Δ > 0인 염색체 0/14 → **지지되지 않음**. 보조 비교 Evo2-7B LLR − phyloP-241m: Δ −0.293 [−0.348, −0.231], 1/14 → 지지되지 않음. (두 비교를 모두 사전 지정했고 다중 비교 보정은 하지 않았다.)
- **대조**: 음성 — 모델 점수를 `match_group` 안에서 섞으면 AUPRC 0.096(NT LLR의 귀무 평균 0.102). 양성 — Evo2-7B LLR vs TSS 거리만: 풀링 Δ +0.266 [+0.213, +0.314], 염색체 평균 Δ +0.231, 13/14 → '지지'.
- **민감도(한 번에 하나)**: baseline을 phyloP-100v / phastCons-43p로 바꿔도 모두 지지되지 않음(Δ −0.550 / −0.394). 염색체 기준 양성 수를 3 / 10으로 바꾸면 17개 중 1개 / 10개 중 0개만 Δ > 0.
- 모듈 03 노트북 02의 AUPRC(NT 0.103, Evo2-7B 0.38, phyloP-241m 0.67, TSS 0.115)와 일치한다. 순열 p는 이 기록의 교차 리뷰 전에는 일치하지 않았다: 노트북 02가 모든 점수에 하나의 귀무분포(그룹 안의 순위 0…9를 섞은 값)를 써서 NT 0.34, TSS 0.006이었다. 관측한 통계량(풀링 AUPRC)의 순열 분포는 점수마다 값을 섞은 것이므로 노트북 02도 같은 방식으로 고쳤고(아래 "교차 리뷰"), 지금은 NT 0.41(이 스크립트는 시드가 달라 0.445; 몬테카를로 표준오차 약 0.015), TSS 0.001이다.
- **템플릿에서 바꾼 것**: 이 트랙은 *학습이 없다(zero-shot)*. `make_split`·`fit_predict`·`PRED`·Ridge·무작위 초기화 모델이 필요 없고, 시드별 Δ 자리를 **염색체별 Δ**로, `MIN_TEST_GROUPS`를 `MIN_POS_CHROM`과 `match_group` 수로 옮겼다. `decide()`는 그대로 쓸 수 있었다. 음성 대조는 "라벨 섞기"가 아니라 "그룹 내 점수 섞기"다.
- **막힌 곳 / 주의**: ① 질문이 "분할 단위를 바꾸려면 좌표가 있는지 먼저 확인"이라고 했는데, 변이표에 `chrom`·`pos`·`match_group`이 있어 염색체 단위가 가능했다. ② 양성이 2~8개뿐인 염색체의 AUPRC는 매우 흔들린다(그래서 최소 양성 수를 사전 지정했다). ③ 직접 계산한 NT LLR은 chr1 변이 210개(양성 21개)뿐이라 MVP로는 부적합하다 — 제공 점수를 썼다.
- **말할 수 없는 것**: 이 변이 집합·이 지표에서의 비교일 뿐 DNA LM 전체나 다른 질병/복합 형질에는 해당하지 않는다. TraitGym 제공 NT 점수의 모델 변형·창 길이는 확인하지 않았다†.
- **미실시였던 것**: 질문의 다른 절반("NT probe의 이득이 층 선택·6-mer baseline 크기에 얼마나 의존하는가")은 NT 임베딩이 캐시에 없어 이 기록에서는 실행하지 않았다. 나중에 [second_halves.md의 B①](second_halves.md)에서 임베딩을 새로 계산해(약 6분) 실행했다.

## 트랙 C — Geneformer 임베딩 위 지도 head vs PCA head
- **설정(고정)**: Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명, 기증자 단위 leave-one-donor-out. head = 로지스틱 회귀(C = 1 고정, 중심화·L2 정규화·표준화는 훈련 기증자만으로 적합). **다만 주 비교의 PCA(HVG, 50) 기준은 HVG 선택·스케일·PCA를 held-out 기증자를 포함한 모든 세포로(라벨 없이) 적합한 transductive 설정이다**(모듈 04 노트북 02와 같은 방식). PCA에 유리한 쪽이고, Geneformer 임베딩에는 이런 적합이 없다. fold별 적합은 민감도에서 따로 본다. 주 비교: V2-104M `<cls>` L-2 vs PCA(HVG, 50), 거친 라벨 13종. 지표: 풀링 macro-F1(기증자 단위 부트스트랩 1,000회) + 기증자별 균형정확도. 결정 규칙: 기증자별 균형정확도 Δ의 평균 ≥ 0.02, Δ > 0인 기증자 ≥ 9/13, macro-F1 Δ 구간 하한 > 0.
- **캐시에서 막힌 곳**: `pbmc_sub.h5ad`에는 세부 라벨(`cell.type.fine`)이 **없고** 세포 이름도 `cell0…`으로 바뀌어 원본과 연결되지 않는다(obs: donor, disease, label, cell_type_cxg, n_counts). 노트북 04/01의 `balanced_subsample`(시드 0, 기증자당 800)이 결정적이라 그것을 `wilk2020_pbmc.h5ad`에 다시 적용했고, 기증자·거친 라벨·cxg 라벨 10,400개가 전부 일치함을 확인한 뒤 세부 라벨 20종을 붙였다 (스크립트가 assert). 새 다운로드는 없다. PCA(HVG)는 캐시에 없어 노트북 04/02와 같은 절차로 만들었다(7초).
- **결과** (거친 13종, 로지스틱 head):

| 표현 | 풀링 macro-F1 | 기증자별 균형정확도 평균 |
|---|---|---|
| PCA(HVG, 50) | 0.856 | 0.841 |
| Geneformer V2 `<cls>` L-2 | 0.838 | 0.806 |
| Geneformer V1 평균 L-2 | 0.724 | 0.691 |
| V1 무작위 초기화 | 0.526 | 0.508 |
| (음성 대조) V2, 훈련 라벨 섞기 | 0.068 | 0.075 (13종 균등 추측 0.077) |

- **주 비교** V2 − PCA: macro-F1 Δ −0.018 [−0.031, −0.009], 기증자별 균형정확도 Δ −0.036, 기증자 3/13 → **지지되지 않음**. 대조 — 사전학습 효과(V1 − V1 무작위 초기화): 풀링 macro-F1 Δ +0.198 [+0.182, +0.223], 기증자별 균형정확도 평균 Δ +0.183, 13/13 → '지지'. (아래 Δ는 따로 적지 않으면 구간과 같은 *풀링 macro-F1* Δ이고, 결정 규칙은 기증자별 균형정확도 Δ의 평균·승수와 이 구간을 함께 본다.)
- **민감도(한 번에 하나)**: PCA를 held-out 기증자를 빼고 fold마다 적합(중심화·L2 정규화는 주 비교와 같게 적용) → Δ −0.015 [−0.031, −0.004], 균형정확도 Δ −0.030, 3/13. head를 kNN(k = 15)으로 → Δ −0.036 [−0.064, −0.018], 균형정확도 Δ −0.090, 0/13(모듈 04 노트북 02의 zero-shot 수치 PCA 0.847·V2 0.811과 같다). 라벨을 세부 20종으로 → Δ −0.079 [−0.097, −0.062], 균형정확도 Δ −0.103, 0/13(PCA 0.824, V2 0.744). 모두 지지되지 않음.
- **읽기**: 지도 head는 격차를 줄였지만(kNN −0.036 → 로지스틱 −0.018) PCA 아래에 머물렀고, 라벨이 세분될수록 격차가 커졌다. 한 데이터셋·head 하이퍼파라미터 1개(C = 1)의 결과다.
- **템플릿에서 바꾼 것**: 시드 대신 **기증자**가 단위이고(분할은 결정적), Ridge/Spearman 대신 로지스틱/macro-F1이다. 음성 대조는 "훈련 라벨 섞기", 무작위 초기화 대조는 캐시에 있는 V1 무작위 초기화 임베딩을 썼다.
- **주의**: ① HVG 선택은 모든 세포로 했다(PCA를 fold별로 적합해도 남는 한계). ② 질병 상태가 기증자에 완전히 겹쳐 있다(COVID 7명·정상 6명). ③ `max_iter = 300`에서 로지스틱 수렴 경고가 13번 나왔다. `max_iter`만 3000으로 올린 사본으로 다시 돌리면 경고가 없고 위 수치가 같았다(음성 대조만 0.068 → 0.069). 경고는 joblib 작업자 프로세스에서 나오므로 스크립트 맨 위의 `warnings.filterwarnings("ignore")`와 무관하게 출력된다(리뷰 후 재실행에서도 13번). `balanced_accuracy_score`의 "y_pred contains classes not in y_true" 경고도 나온다 — 한 기증자의 test에 없는 세포 유형을 예측한 경우이며, 균형정확도는 그 기증자에 실제로 있는 유형만 평균한다. ④ `fold별` PCA도 HVG 선택은 전체 세포로 했다.
- **미실시**: 새 데이터셋, 미세조정, scGPT 등 다른 모델. (라벨 입도 질문은 [second_halves.md의 C①](second_halves.md)에서 실행했고, 위 세 가지는 같은 문서에서 조사만 했다.)

## 공통으로 확인한 것
1. **세 트랙 모두 새 다운로드 없이 캐시만으로 MVP를 끝까지 돌릴 수 있었다.** 막힌 곳은 하나(트랙 C의 세부 라벨)였고 결정적 재현으로 풀렸다.
2. **템플릿 노트북 그대로는 안 되고, 구조는 옮겨 쓸 수 있었다.** 바꾼 것은 데이터 로딩, 특징, 분할/단위(시드 → 염색체·기증자·반복), 지표뿐이었다. `decide()`와 "사전 등록 → 출처 → 점검 → 대조 → 민감도" 순서는 그대로 썼다. 트랙 B처럼 학습이 없는 비교에는 `make_split`/`fit_predict` 인터페이스가 맞지 않는다.
3. **대조는 트랙마다 다시 정의해야 했다.** 음성 대조는 B "그룹 내 점수 섞기", C "훈련 라벨 섞기", D "라벨 섞기"였고, 결정 규칙이 '지지'를 낼 수 있음을 보이는 양성 대조는 B "Evo2-7B vs TSS 거리만", C·D "사전학습 vs 무작위 초기화"였다. 이 양성 대조를 넣지 않았다면 세 트랙의 "지지되지 않음"이 규칙의 편향인지 구분하지 못했을 것이다.
4. 세 주 비교가 모두 "지지되지 않음"으로 나온 것은 질문의 *선택* 때문이기도 하다(FM이 강한 baseline을 이길지 묻는 질문). 새로운 결론이 아니라 모듈 03·04·05의 방향과 같다.

**반영하지 않은 것**

- **`decide()`가 `len(deltas) < MIN_WINS`를 유효 단위 하한으로 쓴다 (agy)**: 템플릿에서 물려받은 것이다. 이 조건에 걸리면 어차피 '지지'가 될 수 없고 라벨만 '판정 불가'로 달라진다. agy가 든 `MIN_POS_CHROM=10` 민감도 경우는 `decide()`를 부르지 않는다.

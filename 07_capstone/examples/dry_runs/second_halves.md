# 트랙 A~D의 "질문의 나머지 절반" 시험 실행 기록 (2026-11-09)

[시험 실행 기록](README.md)은 트랙마다 질문 *하나*(MVP)만 돌렸다. 이 문서는 캡스톤 README §2 표의 질문 중 **그때 실행하지 못한 쪽**을 같은 방식(템플릿 구조: 사전 등록 → 출처 → 데이터 점검 → 분할·누출 → baseline → 평가 → 대조 → 민감도)으로 돌린 기록이다.

> **이 기록의 성격**
> - **학습자 파일럿이 아니다.** 과정을 만든 쪽이 직접, 한 번씩 돌렸다. 소요 시간은 이 Mac(MPS)에서 잰 한 번의 값이다.
> - **실제 사전 등록이 아니다.** 각 스크립트 머리에 *작성자가 이미 본 결과*를 적었다(모듈 노트북의 관련 결과). 결정 규칙·임계값은 실행 전에 코드에 고정했지만 결과를 보기 전에 정했음을 증명할 수 없다.
> - **새 다운로드는 D③의 CSV 3개(승인 후, 합 3.95 MB), C②의 H5AD 1개(승인 후, 150 MB), C④의 scGPT 소스 `.py` 26개(273,078 B)와 whole-human 체크포인트 3개 파일(약 207 MB; 둘 다 승인 후)뿐**이다. 나머지는 캐시만 썼다(임베딩·미세조정 fold 결과는 `.cache/capstone_runs/`에 새로 저장, git 제외). 설치(`pip install`)는 하지 않았다.
> - Codex·agy 교차 리뷰를 받았다(맨 아래 "교차 리뷰" 절).
> - 결과를 "ESM-2/NT/ChemBERTa/Geneformer는 …하다"로 일반화하지 말 것. 각 행은 데이터·모델·head를 고정한 한 번의 비교다.

실행: 저장소 루트에서 `HF_HOME=$PWD/.cache/hf HF_HUB_OFFLINE=1 .venv/bin/python -I <스크립트>`. 실행 기록(`provenance.json`)은 `.cache/capstone_runs/<RUN_NAME>/`에 쓴다.

## C① — 라벨 입도와 zero-shot 순위 (트랙 C)
- **설정(고정)**: Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명, leave-one-donor-out. 표현은 전부 동결, head = 코사인 kNN(k = 15, 모듈 04/02와 같음). 표현 5종: PCA(HVG, 50) · Geneformer V2 `<cls>` L-2 · V2 평균 L-2 · V1 평균 L-2 · V1 무작위 초기화. 입도 3종: 거친 13종 / cellxgene `cell_type` 19종 / 세부 20종(세부는 [트랙 C 스크립트](track_C_head_geneformer_vs_pca.py)와 같은 재현 절차로 복원, assert 통과). 지표 = 풀링 macro-F1, 구간 = 기증자 부트스트랩 1,000회(모든 비교에 같은 재표본 인덱스).
- **주 질문의 정의**: 어떤 표현 쌍에서 거친·세부 Δ의 부호가 반대이고 **둘 다 구간이 0을 제외**하면 "순위가 바뀐다"(지지).

- **판정**: 점추정 순위가 세 입도에서 같고(위 표 위에서 아래 순서), 부호가 뒤집힌 쌍이 없다 → **지지되지 않음**. 다만 PCA − V2 `<cls>` 격차는 +0.036 [+0.018, +0.064] → +0.080 [+0.063, +0.117] → +0.074 [+0.056, +0.114]로 커졌고(세부 − 거친 +0.038 [+0.026, +0.064]), V2 `<cls>` − V1 평균 격차는 +0.260 → +0.212 → +0.230으로 줄었다(세부 − 거친 −0.030 [−0.053, −0.000]).
- **읽을 때 주의**: 변화는 거친 → cellxgene(19종)에서 한 번에 일어나고 cellxgene(19) → 세부(20)에서는 거의 없다. 입도의 *점진적* 효과가 아니라 "13종 라벨 vs 19~20종 라벨" 차이이며, 클래스 수·클래스 크기·라벨 기준이 함께 바뀐다(분리 못 함). 세부 20종은 모두 거친 라벨 하나에 포함됨(위계 점검 0/20 예외).
- **대조**: 사전학습 효과(V1 − V1 무작위): +0.198 / +0.211 / +0.215, 기증자 13/13 → 세 입도 모두 '지지'. 거친 라벨 수치는 모듈 04(PCA 0.847, V2 0.811, V1 = 0.847 − 0.296 = 0.551)와 같다.
- **주의**: PCA 기준은 모듈 04/02처럼 HVG·스케일·PCA를 모든 세포로 적합한 transductive 설정(PCA에 유리). 일부 기증자에 없는 클래스가 거친 6종·cellxgene 10종·세부 11종 있다(풀링 confusion에서 계산하므로 지표는 정의되지만 기증자별 값은 아니다). 기증자 13명, 한 데이터셋, kNN 하나.
- **템플릿에서 바꾼 것**: 단위 = 기증자(트랙 C MVP와 같음). 주 비교의 결정 규칙을 "기증자별 승수"가 아니라 "구간을 고려한 순위 뒤집힘"으로 새로 정의했다(승수 규칙은 사전학습 대조에만 사용).

V2 평균 풀링 → −0.035 [−0.056, −0.017](−0.025, 5/10). 모두 지지되지 않음.
- **Wilk와 같은 방향인가**: 같다 — V2의 zero-shot 임베딩 위 지도 head가 PCA를 이기지 못했다(Wilk 로지스틱 Δ −0.018 [−0.031, −0.009], 기증자 3/13; 여기 −0.041, 4/10). 격차의 크기는 비교할 수 없다 — 라벨 집합(13종 vs Wilk 13종/세부 20종)·플랫폼(5′ vs 3′)·기증자 수(10 vs 13)가 다르다. V1의 PCA 대비 격차(−0.190)가 V2보다 훨씬 크고, 사전학습 효과(V1 − 무작위)가 양수인 것도 Wilk와 같다.
- **주의·미확인**: ① 세포 유형 28종 중 15종을 뺐다(작은 유형의 평가를 못 해서) — 남은 13종은 큰 유형이라 이 결과가 희귀 유형에는 적용되지 않는다. ② 라벨은 원 논문의 자동·수동 주석이며 틀릴 수 있다. ③ PCA는 모든 기증자의 세포로 적합한 transductive 설정이다(held-out 기증자의 특징을 함께 봄). 이 실행에서 엄격 fold별 적합과의 차이는 macro-F1 0.813 vs 0.807로 작았고, 일반적으로 PCA에 유리하다고까지는 말하지 않는다. ③′ 평가할 세포 유형 13종은 *모든 기증자(평가 기증자 포함)의* 세포 수로 정했다(100세포 이상) — 특징·성능이 아닌 라벨 개수로 정한 모집단 정의이지만 held-out 라벨 정보를 쓴 것은 맞다. ④ **Geneformer 사전학습 코퍼스와의 겹침은 확인하지 못했다**⚠️ — 2024년 연구라 V1(2021년 코퍼스)에는 없을 가능성이 높지만 V2(약 1억 세포)는 모른다. ⑤ 로지스틱 `max_iter`는 3,000이라 트랙 C(300)와 수렴 조건이 다르다(트랙 C에서 3,000으로 올려도 수치가 같았다). ⑥ 한 번의 실행, 기증자 10명.
- **계산**: 임베딩 V1 128초 · V1 무작위 초기화 127초 · V2-104M 1,314초(약 22분), 전체 1,641초(Mac MPS). 임베딩은 `.cache/capstone_runs/h2_C_new_dataset_geneformer/`에 입력 키와 함께 저장했다. 엄격 PCA 민감도를 넣은 뒤에는 캐시된 임베딩으로 스크립트를 다시 돌렸고(106초) 기존 수치는 그대로 재현됐다.

## C③ — Geneformer 미세조정 vs 동결 임베딩·PCA (트랙 C)
- **설정(고정)**: Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명 leave-one-donor-out, 거친 라벨 13종(트랙 C MVP·C①과 같은 분할). 모델 = **Geneformer V1-10M**(`ctheodoris/Geneformer` 리비전 `1f7fbae4…`, 모듈 04/01과 같은 허용 목록 unpickler·rank value encoding) — BERT backbone 전체 + 평균 풀링(패딩 제외) + Dropout 0.1 + 선형 head(V1에는 `<cls>`가 없어 공식 첫 토큰 풀러 대신 평균 풀링). **하이퍼파라미터는 고정하고 튜닝하지 않았다**: 2 에폭, 배치 32, AdamW(backbone 5e-5, head 1e-3, weight decay 0.01), 10% 워밍업 + 선형 감쇠, 입력은 상위 순위 유전자 **512개**로 절단, 검증 기반 선택 없음, fold별 시드 = 0 + 기증자 순번. 결정 규칙은 트랙 C MVP와 같고 주 비교는 둘이다: 미세조정 vs PCA(HVG, 50) + 로지스틱, 미세조정 vs 같은 512토큰 입력의 V1 동결 임베딩 + 로지스틱. 작성자는 동결 임베딩 결과(V1 평균 L-2 0.724, PCA 0.856)를 이미 보았고 미세조정 결과는 보기 전에 정했다.
- **V2-104M을 하지 않은 이유**: 같은 설정으로 이 Mac(MPS)에서 약 17분/에폭(약 9,000세포)이라 13-fold LODO는 약 7시간으로 추정해 제외했다(스크립트 작성 전 한 번 잰 값이며 로그는 보존하지 않았다). 따라서 "더 나은 동결 임베딩인 V2(0.838)를 미세조정하면"은 이 기록으로 답할 수 없다.
- **데이터 점검**: 토큰 길이 중앙값 875, 512토큰으로 잘리는 세포 92%(2,048에서 잘리는 세포 0%). 새로 계산한 2,048토큰 V1 동결 임베딩 200개가 모듈 04/01 캐시와 최대 절대차 1.19e-07로 일치한다(토큰화·어휘 순서 점검).
- **결과 (13종, 기증자 13명; PCA·동결 임베딩 행은 로지스틱 head, 미세조정 행은 backbone과 함께 학습한 선형 head)**:

| 표현 | 풀링 macro-F1 | 기증자별 균형정확도 평균 (최소–최대) |
|---|---|---|
| PCA(HVG, 50) | 0.856 | 0.842 (0.75–0.94) |
| PCA 엄격 fold별(필터·HVG·스케일·PCA 훈련 fold만) | 0.854 | 0.841 |
| V1 동결, 2,048토큰(모듈 04/01 캐시) | 0.724 | 0.691 |
| V1 동결, 512토큰 | 0.673 | 0.644 |
| **V1 미세조정, 512토큰** | **0.779** | 0.767 (0.69–0.85) |

- **주 비교**: ① 미세조정 − PCA: 풀링 macro-F1 Δ **−0.077 [−0.092, −0.056]**, 균형정확도 Δ −0.075, Δ > 0인 기증자 **1/13**(H2: 0.85 vs 0.83) → **지지되지 않음**. ② 미세조정 − V1 동결(512토큰): **+0.107 [+0.086, +0.150]**, +0.123, **13/13 → 지지**. 참고: 미세조정 − V1 동결(2,048토큰 캐시) +0.055 [+0.038, +0.095], +0.076, 13/13. 민감도: 미세조정 − 엄격 fold별 PCA −0.074 [−0.089, −0.054](−0.074, 1/13) → 같은 결론.
- **대조**: 양성(사전학습 효과) — 앞의 5개 기증자만, 미세조정 풀링 macro-F1 0.702 vs 무작위 초기화로 같은 방식 미세조정 0.269, 균형정확도 Δ 평균 +0.392, 5/5 양수(사전 규칙 충족). 음성 — 훈련 라벨만 섞은 미세조정 2개 fold(C1, C2): 균형정확도 0.123, 0.091. 균형정확도의 균등 추측 기준은 *그 기증자에 있는 클래스 수*의 역수라 C1 0.083, C2 0.091이다(13종이 다 있는 기증자는 0.077). 두 fold뿐이고 섞은 라벨 모델이 훈련 주변분포 쪽으로 쏠리므로 이 기준선은 근사다 — 신호 없음과 모순되지는 않지만 촘촘한 검정은 아니다(PCA 0.79·미세조정 0.76과는 크게 떨어져 있다).
- **읽는 법**: 미세조정은 V1 동결 임베딩의 격차를 상당히 메운다(같은 512토큰 기준 0.673 → 0.779; 2,048토큰 동결 0.724보다도 높다). 그러나 **PCA에는 이 설정에서 미치지 못한다**(−0.077, 13명 중 12명에서 낮음). 입력을 512로 자르는 것만으로 동결 임베딩이 0.724 → 0.673으로 떨어지므로(−0.051), 512토큰 절단이 미세조정의 천장을 낮췄을 가능성은 이 실행에서 분리하지 못했다.
- **주의·미확인**: ① V1-10M만, 시드 1개, 하이퍼파라미터 고정·무튜닝(README는 튜닝을 강하게 권한다) — 튜닝하면 미세조정이 더 나아질 수 있으므로 이 값은 "이 고정 설정에서의" 결과다. ② V2-104M은 미세조정하지 못했다. ③ 양성·음성 대조는 일부 fold(5, 2개)에서만 돌렸다. ④ 훈련 손실이 에폭 2에서 약 0.35까지 내려갔다(과적합 여부는 검증 fold가 없어 측정하지 않음). ⑤ 평균 풀링 head는 공식 분류 head와 다르다. ⑥ 512토큰 절단 세포 92%. ⑦ PCA는 transductive 설정(엄격 적합과 같은 결론). ⑧ 기증자 13명, 한 데이터셋.
- **재현·검토 이력**: 20개 fold(13 + 대조 7)를 한 번 돌렸고(총 5,454초; 단독일 때 fold당 약 216초, 다른 작업과 동시 실행 구간은 300~420초) 교차 리뷰를 반영한 최종 스크립트로 **캐시된 fold 결과에서 보고서를 다시 만들었다**(55초; 수치 동일). 반영: 출력 라벨의 "500토큰" 표기를 코드(`MAX_LEN = 512`)에 맞게 정정(1차 실행 로그에는 오기가 남아 있다), 재개 캐시를 설정·데이터 지문 디렉터리로 옮김(1차 실행의 설정·데이터 해시·리비전·패키지 버전이 새 지문과 일치함을 확인한 뒤 파일을 이동), `PRIMARY` 표시 오류 수정, 엄격 fold별 PCA 민감도 추가(**사후 분석**).

## C④ — scGPT zero-shot 임베딩 vs PCA·Geneformer (트랙 C)
- **설정(고정)**: C③과 같은 데이터(Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명 leave-one-donor-out, 거친 라벨 13종) — 트랙 C MVP·C①과 같은 분할. 주 비교 = scGPT(whole-human) `<cls>` 임베딩 + 로지스틱 head(C = 1) vs PCA(HVG, 50) + 같은 head. 결정 규칙은 트랙 C MVP와 같다(기증자별 균형정확도 Δ 평균 ≥ 0.02, Δ > 0인 기증자 ≥ 9/13, 풀링 macro-F1 Δ의 기증자 부트스트랩 구간 하한 > 0). 작성자는 같은 데이터에서 Geneformer V2 < PCA를 이미 보았고 scGPT 결과는 보기 전에 정했다.
- **출처(승인 후 내려받음, 설치 없음)**: 소스 = [bowang-lab/scGPT](https://github.com/bowang-lab/scGPT) 커밋 `cebd6fae…`의 `.py` 26개(273,078 B, MIT LICENSE 파일 확인)를 `.cache/scgpt_src/`에 두고 `pip install` 없이 `sys.path`로 불러 쓴다(스크립트가 파일 수·바이트·해시 digest를 assert). 체크포인트 = whole-human의 `best_model.pt`·`vocab.json`·`args.json`(합 약 207 MB, scGPT README의 Google Drive 폴더, sha256을 스크립트가 assert). **체크포인트의 라이선스 표기는 확인하지 못했다**(재배포하지 않는다). 가중치는 `torch.load(weights_only=True)`로만 읽는다. 공식 `embed_data`는 CUDA·`os.sched_getaffinity`(리눅스 전용)를 가정해 그대로 부를 수 없어 같은 입력 구성(`<cls>` + 0이 아닌 유전자, 값은 세포 안에서 51구간 binning, `<cls>`를 포함한 토큰이 1,200개를 넘으면(= 어휘와 연결된 발현 유전자 1,200개 이상) 시드 고정 무작위 표본, `<cls>` 위치의 마지막 층 출력)으로 **자체 임베딩 루프**를 썼다. 이때 `torch.backends.mha.set_fastpath_enabled(False)`가 필요했다(eval 모드 nested-tensor 경로의 연산이 MPS에 없다).
- **데이터 점검**: scGPT 어휘(60,697)와 연결된 유전자 20,347 / 24,505(83%)이고, 연결된 유전자가 가진 카운트가 전체의 99.0%다. 연결된 열 중 어휘 id가 겹치는 것은 없다(별도 점검). `<cls>`를 포함한 토큰이 1,200개를 넘어(발현 유전자 1,200개 이상) 무작위 표본을 뽑은 세포는 2,247 / 10,400(22%)이다. 체크포인트 텐서 163개 중 162개가 이름·모양이 맞게 로드됐고(전부 값 동일성 assert), 로드되지 않은 모델 파라미터 10개는 분류 head `cls_decoder.*`(임베딩에 쓰지 않음)뿐이며 모델에 대응이 없는 체크포인트 텐서는 `flag_encoder.weight` 1개다.
- **공식과 다른 점**: 공식 함수는 반환 직전 `<cls>` 임베딩을 행별 L2 정규화하지만 여기서는 모든 특징에 공통인 파이프라인(훈련 fold 평균 센터링 → L2)을 쓴다. 공식 순서(L2 → 훈련 fold 센터링 → L2)도 민감도로 냈고 결과는 같았다(아래).
- **결과 (13종, 기증자 13명, 로지스틱 head)**:

| 표현 | 풀링 macro-F1 | 기증자별 균형정확도 평균 |
|---|---|---|
| PCA(HVG, 50) | 0.856 | 0.842 |
| **scGPT `<cls>`** | **0.871** | 0.842 |
| scGPT 유전자 위치 평균 | 0.858 | 0.838 |
| Geneformer V2 `<cls>` L-2 | 0.838 | 0.806 |
| Geneformer V1 평균 L-2 | 0.724 | 0.691 |
| scGPT 무작위 초기화 `<cls>` | 0.556 | 0.519 |

- **주 비교** scGPT `<cls>` − PCA: 풀링 macro-F1 Δ **+0.015 [−0.007, +0.033]**, 기증자별 균형정확도 Δ +0.000, Δ > 0인 기증자 6/13 → **지지되지 않음**(macro-F1 점추정은 앞서지만 구간이 0을 포함하고 균형정확도는 동률). 보조 비교(같은 규칙) scGPT − Geneformer V2 `<cls>`: **+0.033 [+0.019, +0.049]**, 균형정확도 Δ +0.037, **12/13 → 지지**. 대조 — 사전학습 효과(scGPT − 무작위 초기화): +0.315 [+0.299, +0.356], 균형정확도 +0.323, 13/13 → '지지'.
- **민감도(한 번에 하나)**: ① 유전자 위치 평균 풀링 − PCA +0.002 [−0.021, +0.023](균형정확도 −0.004, 4/13). ② 공식 순서(L2 먼저) +0.016 [−0.006, +0.033](+0.000, 6/13). ③ PCA를 엄격하게 fold별 적합(유전자 필터·HVG·스케일·PCA 모두 훈련 fold만) — PCA는 0.854로 transductive(0.856)와 −0.002 [−0.010, +0.006]밖에 차이가 없고, scGPT − 엄격 PCA는 +0.018 [−0.008, +0.040](+0.002, 5/13); 같은 기준 V2 − 엄격 PCA는 −0.015 [−0.032, −0.004](−0.035, 1/13). ④ **head를 코사인 kNN(k = 15)으로 바꾸면 방향이 달라진다**: scGPT − PCA −0.033 [−0.048, −0.012](균형정확도 −0.070, 2/13), scGPT − V2 +0.003 [−0.007, +0.027](+0.020, 9/13). kNN의 PCA(0.847)·V2(0.811)는 C①의 거친 라벨 값과 같다. 민감도는 모두 '지지되지 않음'이다(③의 V2 − PCA 포함).
- **읽는 법**: scGPT의 zero-shot `<cls>` 위 지도 head는 이 데이터에서 PCA를 **이기지 못했고 비슷한 수준**이다(로지스틱: 점추정 +0.015, 구간이 0을 포함; kNN: 오히려 아래). Geneformer V2보다는 낫다(12/13 기증자). 즉 "FM이 PCA를 이긴다"도 "항상 진다"도 아니고, 모델·head에 따라 순위가 바뀐다. 기증자별로 보면 scGPT가 PCA보다 높은 곳은 C1·C2·C4·H2·H3 등이고 C7(0.82 vs 0.91)처럼 크게 낮은 곳도 있다.
- **주의·미확인**: ① 입력 구성이 공식 `embed_data`와 완전히 같지는 않다(위 "공식과 다른 점"; 자체 루프). ② 체크포인트 `args.json`은 `no_cls = true`, `no_cce = true`, `MVC = true`로 기록되어 있다 — 이름으로는 분류·대조 손실 끔, GEPC(MVC) 디코더 켬을 뜻하는 것으로 보이지만 **실제 사전학습에서 이 플래그가 그렇게 쓰였는지는 확인하지 못했다**⚠️. `cell_emb_style`은 기록되어 있지 않아 **`<cls>` 위치가 사전학습에서 세포 표현으로 쓰였는지는 확인하지 못했다**⚠️. 그래서 `<cls>`와 유전자 평균 풀링을 둘 다 냈고(결론 동일) `<cls>` 결과를 "`<cls>`가 사전학습된 세포 표현"으로 해석하지 않는다. ③ 무작위 유전자 표본을 뽑은 세포 22%는 시드 고정 표본이라 다른 시드에서의 변화는 재지 않았다. ④ **사전학습 코퍼스와의 겹침은 확인하지 못했다**⚠️(scGPT whole-human은 README 기준 정상 인간 세포 3,300만 개이고, 이 데이터는 COVID-19 환자 PBMC 포함). ⑤ 동결 임베딩 비교다 — 미세조정한 scGPT에 대해서는 말하지 않는다. ⑥ PCA는 모든 기증자로 적합한 transductive 설정이다(위 ③에서 엄격 적합과 거의 같음을 확인). ⑦ 어휘와 연결되지 않은 유전자 17%(카운트 1.0%)는 입력에서 빠졌다. ⑧ 기증자 13명, 한 데이터셋, 로지스틱 head 하나.
- **재현·검토 이력**: 전체를 두 번 실행했고 두 번의 임베딩이 **비트 단위로 같았다**(최대 절대차 0; MPS, 같은 시드·같은 순서). 2차 실행은 교차 리뷰를 반영한 스크립트(가중치 전수 점검, 입력 데이터 해시를 넣은 캐시 키, L2 순서·엄격 PCA 민감도 추가)로 했으며, 이 두 민감도는 1차 결과를 본 뒤에 추가한 **사후 분석**이다. 주 결과 수치는 1차와 같았다.
- **계산(Mac MPS, C③ 미세조정과 동시 실행이라 단독 시간이 아님)**: 임베딩 whole-human 564초 + 무작위 초기화 553초(스모크: 128세포 5초 → 전체 단독 약 7분 환산), 전체 1,507초.

## D② — 표기 증강 vs 정규화 (트랙 D, 모듈 05 과제 2)
- **설정(고정)**: Lipophilicity 4,200, scaffold 분할(노트북 05/01과 같은 함수·시드) 5-fold × 3회, 동결 ChemBERTa-77M-MLM(평균 풀링, 마지막 층) + ridge. 비교: **canon**(정규화 SMILES만 학습) · **avgK**(학습 분자의 무작위 표기 K개 임베딩을 평균) · **rowsK**(K개를 행으로 증강) · K = 1/5/20. test 입력 조건 3종: 정규화 / 분자당 무작위 표기 1개(rand1) / 무작위 표기 5개 평균(tta5). (c) "추론 때 항상 정규화" = canon 학습 + 정규화 test. 학습·test의 무작위 표기는 시드 집합이 서로 다르다(학습 20벌, test 5벌).
- **ridge**: 알파를 변형이 학습하는 입력과 같은 분포(정규화 / 증강 행 / 평균 행)의 **분자(scaffold) 단위 안쪽 3-fold**로 고른다(증강 행은 한 분자가 여러 행이라 RidgeCV의 leave-one-out은 누출이다). canon 변형의 결과는 노트북 05/01과 같다(반복 0: 정규화 0.863, 무작위 표기 1.455 vs 노트북 0.863 / 1.448).
- **결정 규칙**: 주 비교 = rows5 vs canon(둘 다 rand1 test): 반복 3회 모두 개선 + 평균 개선 ≥ 0.10 + 군집 부트스트랩 구간 하한 > 0이면 '지지'. '해결됨'은 추가로 "증강 head의 무작위 표기 RMSE − 정규화 head의 정규화 RMSE ≤ 0.05".
- **결과 (RMSE, 3회 반복 평균 ± sd)**:

- **판정**: rows5의 개선 +0.471 [+0.424, +0.507], 3/3 → **지지**. 그러나 증강 head의 무작위 표기 RMSE(0.983)는 정규화 head의 정규화 RMSE(0.861)보다 +0.123 [+0.100, +0.147] 높다 → **해결되지 않음**. K 1 → 5 → 20은 rand1 RMSE 1.007 → 0.983 → 0.979로 거의 변하지 않는다. 평균(avg)은 단일 입력에서는 맞지 않고(avg20은 정규화 test 1.491), 평균을 test에도 쓰면(tta5) 0.92~0.95까지 내려간다.
- **(c)**: 입력을 통제할 수 있으면 "항상 정규화"가 임베딩 1회로 가장 낮다(0.861). 입력을 정규화할 수 없을 때(이 실험에서는 정규화 입력이 가능한 경우만 비교하지 않았다)의 선택지로 증강을 평가한 것이며, 그때 비용은 학습 임베딩 K배 + (선택) test 평균 1~5회다. 외부 SMILES를 받은 뒤 정규화할 수 있는지는 이 실험이 다루지 않았다. ECFP4(0.806)는 어느 MLM 변형보다 낮아 이 질문의 비교 대상을 바꾸지 않는다.
- **대조**: 양성(문제가 실제로 있는가) canon의 정규화 → 무작위 표기 차이 +0.593, 노트북 §8과 같은 크기. 음성(각 폴드에서 훈련 라벨만 섞음) 1.205 ≈ sd 1.203.
- **주의**: 무작위 표기 집합이 하나(학습 20벌, test 5벌)라 표기 표본 변동은 구간에 들어 있지 않다. 반복 3회는 scaffold 분할만 바꾼다. MPS vs CPU 임베딩 최대 절대차 6.5e-7.

## D⑤ — 거짓 음성 마스킹 (트랙 D, 모듈 05 과제 5)
- **설정(고정)**: 노트북 05/02의 사전 고정 설정(40 에폭, 배치 256, AdamW lr 1e-3, 초기 온도 0.07)과 같은 동결 임베딩·head·InfoNCE. Pfam 묶음 5-fold, seq→text 검색, 갤러리 ≈ 1,479. 변형: **base** · **mask**(같은 Pfam 그룹이거나 글자까지 같은 텍스트인 비대각 쌍을 로짓에서 제외) · **sampler**(배치마다 그룹을 크기에 비례해 비복원으로 256개 뽑고 그룹당 한 쌍). 학습 시드 3개.

- **대조**: 양성(정렬 학습 vs 짝 섞기) ΔR@1 +0.0141 [+0.0115, +0.0185] 3/3 → 지지. 음성: 짝 섞은 R@1 0.0004(우연 0.0007).
- **주의**: sampler는 그룹을 크기에 비례해 뽑아 학습 분포가 base와 다르다(과제의 (b)와 세부가 같지 않을 수 있음). 시드는 초기화·배치 순서만 바꾼다(폴드는 고정).

- **(b) MLM − 무작위 초기화**: FreeSolv·BACE는 세 분할 모두 지지(예: FreeSolv +0.783 / +1.762 / +0.685, BACE +0.057 / +0.052 / +0.078). ClinTox는 random만 지지(+0.058 [+0.007, +0.111]); scaffold(+0.043 [−0.012, +0.093])·군집(+0.049 [−0.005, +0.109])은 3/3 반복이 양수여도 구간이 0을 포함해 지지되지 않음.
- **참고**: RDKit-217이 FreeSolv(1.06~1.25)와 ClinTox에서 가장 낮은 오차·높은 AUC다. FreeSolv가 제공하는 계산값(`calc`)의 RMSE는 1.542(y sd 3.848)로 선형 RDKit-217보다 나쁘다 — 학습 baseline이 아닌 물리 기반 값과의 단순 비교일 뿐이다. MTR − MLM은 FreeSolv random/군집에서만 구간이 0을 제외했다(+0.285, +0.327).
- **대조**: 음성(각 폴드의 *훈련* 라벨만 섞은 ECFP4, 순열 10회, scaffold, 원래 test 라벨로 평가): FreeSolv RMSE 평균 3.873(sd 0.020; y sd 3.845), BACE AUROC 평균 0.499(sd 0.046, 범위 0.423~0.578), ClinTox 0.506(sd 0.055, 범위 0.394~0.603) — 0.5 근처다. **첫 실행은 전체 라벨을 한 번 섞어 모든 폴드에 쓰고 원래 라벨로 평가했는데 BACE 0.458·ClinTox 0.437로 0.5보다 낮게 치우쳤다**(교차 리뷰의 지적 뒤 폴드 안 순열로 바꿨다). 임시 점검에서는 같은 전체 순열을 *섞은 라벨*로 평가하면 0.494·0.515였다(스크립트에 포함하지 않음). 이 설계가 왜 아래로 치우치는지는 확인하지 못했다. 양성 대조는 (b)가 대신한다(FreeSolv·BACE에서 지지).
- **④ 사전학습 겹침**: ChemBERTa-77M은 PubChem 분자로 사전학습되었다고 알려져 있다(†모델 카드 없음). 이 세 데이터의 분자가 PubChem에 있을 가능성이 높으나(특히 FreeSolv·BACE) 확인하지 않았다. 겹침이 이 비교에 어느 방향으로 얼마나 영향을 주는지는 측정하지 않았다(겹침이 MLM에 유리할 것이라는 것은 가설이다†).
- **주의**: scaffold 분할이 FreeSolv에서는 사실상 random에 가깝다(acyclic 50%). 한 번의 실행, 표현별 튜닝 없음.

## B① — NT probe의 이득이 의존하는 것 (트랙 B)
- **설정(고정)**: 모듈 03/01의 프로모터 분류(`promoter_tata` train 5,062 / test 212, `promoter_no_tata` train 6,000(30,000 중 무작위) / test 1,372; test는 chr20·chr21, train과 염색체가 겹치지 않음). NT-500M 평균 임베딩(특수 토큰·패딩 제외)을 **층 0~24의 짝수 층 13개**에서 뽑고 표준화 + 로지스틱 probe, C는 train 안의 염색체 단위 3-fold(AUROC)로 선택. baseline = k-mer 빈도(k = 3~7, 차원 64~16,384). 학습 크기 n = 500~6,000.
- **결정 규칙**: train CV로 고른 층 − 6-mer의 ΔAUROC ≥ 0.01 이고 test 재표본 95% 구간 하한 > 0, **두 과제 모두**일 때 '지지'.
- **주 비교**: promoter_tata 층 12 Δ +0.001 [−0.030, +0.029](NT 0.925 vs 0.925, 지지되지 않음); promoter_no_tata 층 16 Δ +0.010 [+0.004, +0.017](0.947 vs 0.936, 지지). 전체 → **지지되지 않음**. 모듈 03/01의 값(tata 층 12 +0.001, no_tata 층 18 +0.010 [+0.003, +0.017])과 일치한다.
- **의존성**:
  - **층**: Δ(고정 층 − 6-mer)는 tata에서 층 0~8(−0.033~−0.022), no_tata에서 층 0~6(−0.022~−0.002)까지 음수였다가 층 10부터 둘 다 양수가 된다. 층별 Δ 범위 tata −0.033~+0.022, no_tata −0.022~+0.012. 선택 방식: tata는 CV가 층 12(Δ +0.001)를 골랐지만 마지막 층 24는 +0.021, test 오라클 층 22는 +0.022; no_tata는 CV 층 16 +0.010, 마지막 층 +0.008, 오라클 층 14 +0.012. tata에서 구간이 *양수 쪽으로* 0을 제외한 층은 없다(층 2·4·6은 음수 쪽으로 제외; test 212개).
  - **baseline k**: no_tata의 NT 이득은 k = 3 +0.024 → 4 +0.017 → 5 +0.014 → 6, 7 +0.010으로 줄지만 모든 k에서 지지된다. tata는 k = 3(+0.037 [+0.004, +0.072])에서만 지지되고 k = 4(+0.010)부터 구간이 0을 포함하며 k = 7에서 −0.011이다. baseline의 크기가 이득의 크기를 정한다.
  - **학습 크기 n(층 후보 {6, 12, 18, 24}, 같은 n의 6-mer와 비교)**: no_tata Δ +0.015 / +0.013 / +0.013 / +0.018 / +0.010 (n = 500 / 1,000 / 2,000 / 4,000 / 6,000), 뚜렷한 추세 없음. tata는 −0.012~+0.010으로 어디서도 구간이 0을 제외하지 못했다(tata의 train은 5,062개뿐이라 n = 6,000 행은 실제로 5,062개 전부다). **경계 주의**: n = 6,000에서 층 후보를 4개로 제한하면 CV가 층 18을 골라 Δ가 +0.010으로 표시되지만 반올림 전 값이 임계값(0.01) 아래라 '지지되지 않음'인 반면, 13개 층에서는 층 16의 Δ가 +0.010(임계값 이상) → '지지'였다. 같은 과제·같은 데이터의 비교가 임계값 근처의 반올림 한 자리 미만 차이로 갈린다(정확한 값은 기록하지 않았다).
- **대조**: 양성(사전학습 효과, NT − 무작위 초기화 NT, 각각 CV로 층 선택): tata +0.128 [+0.070, +0.185], no_tata +0.101 [+0.085, +0.120] → 지지. 무작위 초기화 NT는 6-mer보다 −0.128 / −0.091 낮다. 음성(훈련 라벨 섞기 10회): NT 층 18 AUROC 평균 tata 0.495(sd 0.051, 범위 0.430~0.595), no_tata 0.504(sd 0.056, 범위 0.403~0.606); 6-mer 0.495 / 0.497. **한 번의 순열은 0.5에서 ±0.1까지 벗어난다**(첫 실행에서 한 번의 값 0.606을 봤고 순열 10회로 바꿨다).
- **주의**: test 염색체 2개라 구간은 test 서열 재표본(인접 창의 상관을 무시해 낙관적)이며 **CV로 고른 층을 고정한 채** 재표본하므로 층 선택의 변동은 구간에 들어 있지 않다. no_tata는 train 30,000 중 6,000만 썼다. NT는 test 염색체를 포함한 GRCh38 전체로 사전학습되어 비교가 대칭이 아니다. test 오라클 층은 진단용이다. 층 간격 2, 평균 풀링 하나만 봤다. 임베딩 약 1.0 GB를 `.cache/capstone_runs/h2_B_nt_layer_kmer_dependence/`에 저장했고, 다시 읽을 때 데이터 스냅샷·모델 스냅샷·하위표본·서열 해시로 만든 키를 확인한다(리뷰 후 추가).

- **읽을 때 주의**: 안쪽 검증이 위치 블록 1~2개 수준이라(블록 크기 10: DN7A 6블록 → 검증 1블록, IF1 8블록·A0A247D711 9블록 → 검증 2블록) 매우 작다 — 고른 (LR, 에폭)의 검증 Spearman(예: DN7A 시드 2 전체 0.697)과 test(0.396)가 크게 어긋나는 시드가 많다(A0A247D711 시드 1 LoRA 검증 0.425 → test −0.092). 선택된 에폭이 1~8으로 시드마다 달랐다. **스케줄 차이**: 선택 설정은 8에폭 스케줄에서 e*에서 멈춰 LR이 0까지 감쇠하지 않고, 고정은 5에폭 스케줄이다 — 선택 효과와 스케줄 효과가 섞여 있다. 3시드라 구간은 계산하지 않았다. 별도 대조(양성·음성)는 만들지 않았고, 고정 설정이 노트북 06/01을 재현한 것이 대조 역할을 한다(위치 baseline B2 대비 LoRA 고정 −0.158, 전체 고정 −0.027로 노트북과 같은 방향). 심화(LP-FT 등)는 하지 않았다.

## 공통으로 확인한 것
1. **템플릿 구조는 이번에도 옮겨 쓸 수 있었다.** 바꾼 것은 단위(시드 → assay·기증자·반복·층)와 지표뿐이었고 `decide()`의 구조는 그대로였다. 단위가 assay일 때는 test 군집이 8개 미만이라 assay별 구간을 못 만들고 assay 부트스트랩으로 올라가야 했다.
2. **음성 대조는 한 번의 라벨 순열로는 0.5 근처가 아니고, 설계에 따라 치우친다.** B①(NT probe)에서 첫 실행의 순열 1회가 0.606이었고 10회 분포는 0.5 ± 0.05였다. D③의 첫 설계(전체 라벨을 한 번 섞어 원래 라벨로 평가)는 10회 평균이 0.44~0.46으로 0.5보다 아래였고, 폴드 안에서 훈련 라벨만 섞는 설계로 바꾸니 0.50~0.51이 되었다. 음성 대조는 여러 순열로, 훈련 라벨만 섞어 보고하고 임의 방향 probe의 AUC 변동이 크다는 점을 기대치에 넣어야 한다.
3. **양성 대조가 항상 '지지'를 내지는 않는다.** A②의 사전학습 효과(8M 위치 probe vs 무작위 초기화)는 구간이 0을 포함했다 — 대조가 약하면 대조를 바꾸거나 이유를 적어야 한다.
4. **임계값 경계 주의.** B①에서 같은 비교가 반올림하면 같은 +0.010인데 층 후보 수에 따라 '지지되지 않음'/'지지'로 갈렸다. 사전 지정한 최소 효과를 쓰되 경계 근처 결과는 판정이 아니라 수치로 읽어야 한다.
5. **세 주 비교의 방향은 새로 얻은 결론이 아니라 모듈 03~06과 일치**했다: 단순 baseline이 강하고(위치 B2, k-mer, ECFP4), FM 이득은 작거나 설정에 의존한다.

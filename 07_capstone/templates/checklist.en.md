# Pre-Submission Checklist

> **English translation.** AI-assisted translation of the [Korean original](checklist.md). The Korean original is authoritative and may be newer. Links to pages without an English version open the Korean original.

This collects what was **actually wrong, or easy to get wrong,** in modules 01–06 of this course. The number in parentheses is the module where it was first encountered. For every item, write yes/no/not applicable and the evidence (file, cell).

## Data and provenance
- [ ] Recorded the hashes, versions and releases of the data files (UniProt content changes with each release: 05)
- [ ] Models are loaded from the **local path** of a `snapshot_download`, with the **revision pinned** (opening by repository ID once mixed in files from an automatic-conversion PR branch: 05)
- [ ] Remote code (`trust_remote_code`) is used only at a revision that you read and pinned. Pickle checkpoints are read through the `weights_only` path (05)
- [ ] For gated models and data, **the user personally** agreed to the terms (05)
- [ ] For licenses, wrote the **evidence (file/API field)**, and wrote "unverified" for what could not be checked. If it is unverified, limited the scope of release and redistribution (06)
- [ ] Merged identical sequences, molecules and texts **before splitting**. Wrote down how label conflicts were handled (05: 33 duplicate sequences straddled train and test)

## Split
- [ ] Wrote down the leakage paths the split is meant to block and the **paths it cannot block** (01, 05)
- [ ] **Measured leakage with numbers** after the split (test→train nearest-neighbor similarity, fraction of shared positions/families) (05: even with the scaffold split, 26% of the test set had Tanimoto ≥ 0.7)
- [ ] Checked the **number of positions/groups** in test. This number is a proxy for the effective sample size, not the number of rows. When it is small, the variation of a single seed is large (07 template: 2 test clusters, and the negative diagnostic varied by ±0.3 across seeds)
- [ ] There are enough groups for the split and the inner CV (07 template: in a length-55 protein, block 15 gave only 4 groups)

## Baselines and controls
- [ ] Included a baseline that **learns no parameters** (nearest-neighbor transfer, mean of the nearest train position. It uses train labels but estimates only on train) (02, 05, 07)
- [ ] Included a simple feature baseline (one-hot · composition · fingerprint · descriptors · a small descriptor set) (02, 05)
- [ ] Created the random-init control **fresh** for each seed (with only one, the luck of that initialization becomes the conclusion) (04, 05, 07)
- [ ] Added a selection-effect control (if the procedure picks the best of thousands of candidates on train, use a random-candidate control) (06)
- [ ] The negative control (shuffling labels · shuffling inputs) is **a diagnostic, not a proof**. Check whether the mean is near 0, together with the seed variation, write it in the report, and investigate the cause if it deviates (05, 07)

## Procedure
- [ ] Fitted standardization · PCA · regularization selection · feature selection **only inside the training fold** (04: PCA saw the held-out data, 06: Ridge standardization)
- [ ] Settings (layer · epochs · LR · threshold) were fixed in advance or chosen with a validation split. The sensitivity table is for reporting (04, 06)
- [ ] Sampling is random. Did not use the front part of the processing order (by length, etc.) (06: 200,000 residues for PCA)
- [ ] Both the split and the initialization change with each seed. Within a seed, all methods use the same train/test (04)

## Evaluation and statistics
- [ ] Defined in advance what the metric is *estimating* and its computation rules. E.g., AUROC was computed per fold and averaged (if pooled, even a constant prediction deviates from 0.5) (05)
- [ ] For retrieval metrics, decided and wrote down the gallery size and the **tie-handling rule** in advance (the rule that disadvantages the correct answer is the conservative one) (05: one tie definition inflated the R@1 of the nearest-neighbor transfer baseline by 1.5–2.3 times)
- [ ] Made comparisons **paired**. The interval is a bootstrap over the correlation unit (group), and I noted that it is a **conditional interval**. Use it **only when there are enough test clusters**. With 2–3 clusters there are only a few possible resamples and the interval is meaningless, so do not compute it and write why (04, 05, 07)
- [ ] When there are about 3 seeds, reported per-seed values instead of an interval. Seed repeats that re-split the same data are **not independent repeats** (the test sets overlap) (06, 07)
- [ ] Distinguished the "difference of medians" from the "median of differences" (05, 06)
- [ ] Reported sensitivity that changes one factor at a time (05, 06)

## Writing
- [ ] Copied the report's numbers from **sentences generated by code**, and checked the text against the run output (04, 05: mismatches in times and values recurred)
- [ ] If a measured metric is a **proxy**, wrote its name and its limits (06: MPS memory is not the peak)
- [ ] Wrote negative and unexpected results as they are, and limited them with "in this setting" (04)
- [ ] Distinguished directly supported / hypothesis / cannot be said, and there is a **list of what was not done** (04–06)
- [ ] Marked statements that could not be verified with † (all modules)

## Reproduction
- [ ] Ran **from start to finish** in a clean environment. The code cells of the executed copy are the same as the submitted notebook (04–06)
- [ ] Ran notebooks that measure time without overlap with other GPU/CPU jobs (06)
- [ ] Recorded hardware and environment quirks (06: on macOS, `torchrun` needed `--local-addr=127.0.0.1`)
- [ ] Recorded failed runs and fixed errors (e.g., a wrongly written revision hash was corrected by checking it against the API: 06)

## Review and accountability
- [ ] Got an independent review (recorded to whom you sent what, and whether information was shared between reviewers), **verified each point with code and output**, and wrote the grounds for accepting or rejecting it (05, 06, 07)
- [ ] Wrote down the dual-use review and the decision on the scope of release. Marked the items that need a check against your institution's policy (06)
- [ ] Did not do downloads or installs that the user had not approved (all modules)

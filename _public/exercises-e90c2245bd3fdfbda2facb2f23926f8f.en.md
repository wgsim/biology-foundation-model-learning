# Module 07 Exercises (Milestones)

> **English translation.** AI-assisted translation of the [Korean original](exercises.md). The Korean original is authoritative and may be newer. Links to pages without an English version open the Korean original.

The whole capstone is the exercise. For each milestone, check for yourself whether you meet the **evaluation criteria**, and leave the results and changes in the [experiment log](../00_orientation/experiment_log_template.en.md) and in the change log of the proposal. Report every metric together with seeds and intervals, and **write the design before seeing the results**. If a download or an installation is needed, write down the file, source, size and license, and do it after getting the user's approval.

## M1 — Question and proposal (preregistration)  *(2–3 hours)*
Fill in the [proposal template](templates/proposal_template.en.md). The items are the track, a one-sentence question, the claim scope and **what cannot be said**, the data source and license grounds, the deduplication rule, the split and how to measure leakage, the comparison targets (a baseline that learns no parameters · simple features · random initialization · the model), one primary metric · one primary comparison · the decision rule, how settings are selected, sensitivity and negative controls, accountability, and the schedule.
- Evaluation criteria: ① the question is **falsifiable**, and the decision rule is defined as one function in code so that "supported/not supported" can be judged, ② the leakage paths that the split blocks and those it fails to block are written down, ③ the list of needed downloads and installations (file, source, size) and whether they were approved, ④ a time estimate showing that it fits in 16–20 hours (extensions separated after the MVP), ⑤ the proposal was committed before the results and its hash recorded (a date alone cannot show that it was not written after the fact).

## M2 — Data, split, baselines  *(3–4 hours)*
Start from the structure of the [template notebook](templates/capstone_notebook_template.ipynb) (only the `✏️` cells are changed). Run the provenance record (hash, revision, version), the data inspection (assert), deduplication, the split, the **per-split leakage table**, and the baselines and negative controls.
- Evaluation criteria: ① hashes, revisions, package versions and the commit in `provenance.json`, ② the number of merged duplicates and the handling of label conflicts, ③ a table of numbers for the overlap with train for each split (e.g., the fraction of shared positions/families, the test→train nearest similarity). Present numbers, not the name of the split, ④ at least 3 baselines (one that learns no parameters · simple features · a random initialization created fresh for each seed) are evaluated with the **same procedure**, ⑤ the negative diagnostic (shuffling labels/inputs): report whether the seed mean is near 0 together with the seed variation, the test positions and the number of groups, and if it deviates, investigate leakage and bugs ("passed = no leakage" is not the case), ⑥ check whether there are enough groups for the split and the inner CV, and whether there are enough test clusters to use a group bootstrap (a guard on the minimum number of clusters).

## M3 — Primary experiment  *(3–4 hours)*
Run the pre-specified primary comparison **once**. Report the paired Δ on the same split, the per-seed values, the group-bootstrap interval over the correlation unit (only when there are enough test clusters; state that it is a conditional interval. If there are too few, do not compute it and write the reason), and the verdict of the decision-rule function.
- Evaluation criteria: ① the decision rule was applied **to the letter** (not changed even if you do not like the result. If you changed it, write in the change log the date, the reason and whether it was after seeing the result), ② the settings (layer, epochs, LR, threshold) were fixed in advance or chosen with a validation split, and not chosen on the test set, ③ the preprocessing fitted only inside training (standardization, PCA, regularization, feature selection), ④ if there are few seeds, per-seed values instead of an interval, ⑤ the metric definition (pooling, ties, gallery, the per-fold mean of AUROC) was written down.

## M4 — Sensitivity, controls, extension  *(2–3 hours)*
Sensitivity that changes one factor at a time (at least one of split unit/size, layer, regularization range, model size), random-initialization and selection-effect controls, and, if the MVP is done, one extension.
- Evaluation criteria: ① state that the settings were *not chosen* with the sensitivity results (that they are for reporting), ② describe how the conclusion depends on the settings (does it flip, does it get stronger), ③ which part of the conclusion the controls rebut or reinforce, ④ mark the extension **separately** from the MVP result (exploratory analysis).

## M5 — Report  *(3–4 hours)*
Write 4–6 pages with the [report template](templates/report_template.en.md). Copy the numbers from **sentences that code generated** in the notebook.
- Evaluation criteria: ① within the 5-line summary, the question, setup, primary result (numbers + interval), verdict and the key limitation, ② what was changed from the preregistration, ③ the distinction between directly supported / hypothesis / cannot be said, ④ report negative and unexpected results as they are, ⑤ a **list of what was not done and what could not be confirmed** (licenses, other data, other hardware, etc.), ⑥ the reproduction method (a record that it runs to the end in a clean environment), ⑦ check every number in the text against the run output (an automatic checking script is recommended).

## M6 — Checklist, independent review, self-assessment  *(2–3 hours)*
Fill in the [checklist](templates/checklist.en.md) and score yourself with the [rubric](templates/rubric.en.md). Get a read-only review from **two or more models** (or humans) with the [review prompt](templates/review_prompt_template.txt), **verify each point** against the code and output, and make a table of `point | how verified | verdict (accepted/rejected/partial) | change`. After fixing, re-run the notebook from the start.
- Evaluation criteria: ① the review bundle states **what you could not confirm and the errors you fixed along the way**, and records to whom you sent what and whether information was shared between reviewers (if you have no model access, substitute a human review or a separated self-check after some time, and state that the independence is weak), ② for each accepted point there is a reproducible check (code, output), and for each rejected point there are grounds, ③ after fixing, the code cells of the executed copy are the same as the submitted notebook, ④ the rubric scores have the **location of the evidence**, and the red-flag self-check was done, ⑤ a discussion of the dimensions where your own score and the reviewer's score differ a lot.

## Optional extension — peer-review simulation
Write **5 questions from an imaginary reviewer** who rebuts the report, and either answer them with data ("confirmed with an additional experiment / could not be confirmed") or move them into the limitations. Score another learner's report with the same rubric to calibrate the criteria.

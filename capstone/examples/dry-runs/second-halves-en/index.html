Dry-Run Record of the “Other Half of the Question” for Tracks A–D (2026-11-09)

English translation. AI-assisted translation of the Korean original. The Korean original is authoritative and may be newer. Links to pages without an English version open the Korean original.

The dry-run record ran only one question (the MVP) per track. This document records running, in the same way, the side that could not be run then, among the questions in the table of capstone README §2. The template structure is preregistration, provenance, data inspection, split and leakage, baselines, evaluation, controls, sensitivity, in that order.

What this record is

  • It is not a learner pilot. The people who made the course ran each one themselves, once. The times are single values measured on this Mac (MPS).

  • It is not a real preregistration. At the head of each script, the results the author had already seen (the related results of the module notebooks) were written. The decision rules and thresholds were fixed in the code before the run, but it cannot be proven that they were decided before the results were seen.

  • The only things newly downloaded were the 3 CSVs of D③ (after approval, 3.95 MB in total), the 1 H5AD of C② (after approval, 150 MB), the 26 scGPT source .py files of C④ (273,078 B) and the 3 files of the whole-human checkpoint (about 207 MB). The last two were also downloaded after approval. Everything else used only the caches. The embeddings and the fine-tuning fold results were newly saved in .cache/capstone_runs/ and excluded from git. Nothing was installed (pip install).

  • It received Codex and agy cross-review (see the “Cross-review” section at the bottom).

  • The results are not to be generalized to “ESM-2/NT/ChemBERTa/Geneformer are …”. Each row is one comparison with the data, the model and the head fixed.

Run: from the repository root, HF_HOME=$PWD/.cache/hf HF_HUB_OFFLINE=1 .venv/bin/python -I <script>. The run record (provenance.json) is written to .cache/capstone_runs/<RUN_NAME>/.

C① — Label granularity and the zero-shot ranking (track C)¶

  • Setup (fixed): Wilk 2020 PBMC 10,400-cell subsample, 13 donors, leave-one-donor-out. All the representations are frozen, and the head is cosine kNN (k = 15, the same as module 04/02). There are 5 representations: PCA (HVG, 50), Geneformer V2 <cls> L-2, V2 mean L-2, V1 mean L-2, V1 random initialization. There are 3 granularities: coarse 13 classes, cellxgene cell_type 19 classes, fine 20 classes. The fine labels were reconstructed with the same reproduction procedure as the track C script and passed the assert. The metric is the pooled macro-F1, and the intervals were obtained with 1,000 donor-bootstrap resamples (the same resampling indices for all comparisons).

  • Definition of the primary question: For a pair of representations, if the signs of Δ for the coarse and fine labels are opposite and the intervals of both exclude 0, we regard “the ranking changes” (supported).

  • Results (pooled macro-F1 [95%]):

  • Verdict: The point-estimate ranking is the same at the three granularities (the order from top to bottom of the table above) and no pair flipped sign, so it is not supported. However, the PCA − V2 <cls> gap grew in the order coarse, cellxgene, fine as +0.036 [+0.018, +0.064], +0.080 [+0.063, +0.117], +0.074 [+0.056, +0.114] (fine − coarse +0.038 [+0.026, +0.064]). The V2 <cls> − V1 mean gap shrank to +0.260, +0.212, +0.230 (fine − coarse −0.030 [−0.053, −0.000]).

  • Caution in reading: The change happens all at once going from the coarse labels to cellxgene (19 classes), and hardly at all going from cellxgene (19 classes) to fine (20 classes). It is not a gradual effect of granularity but a difference of “13-class labels vs 19–20-class labels”, and the number of classes, the class sizes and the labeling criteria change together, so they cannot be separated. Each of the 20 fine classes falls within a single coarse label (0/20 exceptions in the hierarchy check).

  • Control: The pretraining effect (V1 − V1 random) is +0.198, +0.211, +0.215 with 13/13 donors, so it is ‘supported’ at all three granularities. The numbers of the coarse labels are the same as in module 04 (PCA 0.847, V2 0.811, V1 = 0.847 − 0.296 = 0.551).

  • Caution: As in module 04/02, the PCA baseline is a transductive setting that fits HVG, scaling and PCA on all cells (favoring PCA). There are classes that are absent in some donors: 6 in the coarse labels, 10 in cellxgene and 11 in the fine labels. The metric is computed from the pooled confusion, so it is defined, but it is not a per-donor value. There are 13 donors, and one dataset and one kNN each.

  • What was changed from the template: The unit is the donor (the same as the track C MVP). The decision rule of the primary comparison was newly defined not as “the number of donor wins” but as “a rank flip that takes the interval into account”. The win-count rule was used only for the pretraining control.

C② — The same comparison on a new single-cell dataset (track C)¶

  • Data (downloaded after approval): CELLxGENE “Cross-sectional” is the PBMC of an HIV-coinfected visceral leishmaniasis study (Commun Biol 2024, doi 10.1038/s42003-024-06225-2). 1 H5AD file, 150,017,626 B, https://datasets.cellxgene.cziscience.com/829fdf60-add0-4ca3-9b2f-dd86b3083885.h5ad, sha256 98a84e43ce2f… (the script asserts it), placed in .cache/singlecell/ (excluded from git). The license is as follows. The Zenodo record of the same study (10.5281/zenodo.10887674) is CC BY 4.0 (checked by API). The license notation of the CELLxGENE file itself could not be confirmed, and it is not redistributed. Nothing was installed.

  • Setup: The rank value encoding and the embedding extraction of module 04/01 were carried over as they are and applied to this data, and then the track C MVP was reproduced. The notebook functions cannot be imported, so they were copied, and the allow-list unpickler was kept. The primary comparison is Geneformer V2-104M <cls> L-2 + a logistic head (C = 1) vs PCA (HVG, 50) + the same head, leave-one-donor-out at the donor level, with the cell_type of the original data as the labels. There are three decision rules: the mean of the per-donor balanced-accuracy Δ ≥ 0.02, donors with Δ > 0 ≥ 70%, and the lower bound of the donor-bootstrap interval of the pooled macro-F1 Δ > 0. The author had already seen the same comparison (V2 < PCA) on the Wilk data, and fixed the setup before seeing the result on this data.

  • Data inspection: The original has 17,308 cells and 35,477 genes, raw.X is integer counts, and the gene IDs are Ensembl. There are 10 donors (8 patients and the healthy controls HEC1 and HEC2, 773–3,711 cells), and since each donor has only one disease status, the donor and the disease status cannot be separated (confounded; donors are nested within the disease group). A balanced subsample of 9,298 cells was made with at most 1,000 cells per donor, and then 15 cell types with fewer than 100 cells (500 cells) were left out of the evaluation (a rule fixed in advance, from 28 types to 13, 8,798 cells). 41% of the evaluation cells are is_primary_data = False in CELLxGENE. According to the official Census documentation, cells that duplicate another dataset in the corpus are False, and which dataset they overlap and whether it affects the results could not be confirmed⚠️. For some donors (0104, 0114, 0117, 0170), all the cells fall in this category. The tokenization results are as follows. V1 has 19,512 columns linked to the vocabulary, a median length of 1,487.5, and 14% of the cells truncated at 2,048 tokens. V2 has 19,263 columns, a median of 1,490 and 0% truncated. The maximum absolute difference of the padding-invariance check (alone vs batch) is 3e-8.

The sizes of the gap cannot be compared, because the label sets (13 classes vs Wilk’s 13 classes/fine 20 classes), the platform (5′ vs 3′) and the number of donors (10 vs 13) differ. In this run the difference from strict per-fold fitting was small, macro-F1 0.813 vs 0.807, and we do not go so far as to say that it generally favors PCA. ③′ The 13 evaluated cell types were defined as the types with 100 or more cells across all donors (including the evaluation donor). It is a population definition fixed by the number of labels, not by features or performance, but it is true that held-out label information was used. ④ The overlap with the Geneformer pretraining corpus could not be confirmed⚠️. It is a 2024 study, so it is likely not in V1 (pretrained in month 6 of 2021, a corpus of about 29.9 million cells, 561 public datasets), but for V2 (about 104 million cells, non-cancer) it is unknown. The model/dataset card gives the source only as “public data such as GEO and HCA”, and says the list of datasets is on the side of the Nature 2023 paper, but that list was not opened. ⑤ The logistic max_iter is 3,000, so the convergence condition differs from track C (300) (raising it to 3,000 in track C gave the same numbers). ⑥ It is a single run and there are 10 donors.

  • Computation: The embeddings took 128 seconds for V1, 127 seconds for V1 random initialization and 1,314 seconds (about 22 minutes) for V2-104M, and the total was 1,641 seconds (Mac MPS). The embeddings were saved together with the input keys in .cache/capstone_runs/h2_C_new_dataset_geneformer/. After the strict-PCA sensitivity was added, the script was re-run with the cached embeddings (106 seconds) and the earlier numbers were reproduced as they were.

C③ — Geneformer fine-tuning vs frozen embeddings and PCA (track C)¶

  • Setup (fixed): Wilk 2020 PBMC 10,400-cell subsample, leave-one-donor-out over 13 donors, 13 coarse labels (the same split as the track C MVP and C①). The model is Geneformer V1-10M (ctheodoris/Geneformer revision 1f7fbae4…; the same allow-list unpickler and rank value encoding as module 04/01). The configuration is the whole BERT backbone + mean pooling (excluding padding) + Dropout 0.1 + a linear head, and since V1 has no <cls>, mean pooling was used instead of the official first-token pooler. The hyperparameters were fixed and not tuned: 2 epochs, batch 32, AdamW (backbone 5e-5, head 1e-3, weight decay 0.01), 10% warmup + linear decay, the input truncated to the top-ranked 512 genes, no validation-based selection, per-fold seed = 0 + donor index. The decision rule is the same as the track C MVP, and there are two primary comparisons. One is fine-tuning vs PCA (HVG, 50) + logistic, and the other is fine-tuning vs the V1 frozen embeddings of the same 512-token input + logistic. The author had already seen the frozen-embedding results (V1 mean L-2 0.724, PCA 0.856) and fixed the setup before seeing the fine-tuning results.

  • Why V2-104M was not done: With the same setting it took about 17 minutes/epoch (about 9,000 cells) on this Mac (MPS), so 13-fold LODO was estimated at about 7 hours and it was excluded (a value measured once before writing the script, and the log was not kept). So the question “what if the better frozen embedding, V2 (0.838), is fine-tuned” cannot be answered by this section (it was later run on a Colab A100: C③-V2 below).

  • Data inspection: The median token length is 875, and 92% of the cells are truncated at 512 tokens (0% are truncated at 2,048). The newly computed 200 frozen embeddings of V1 at 2,048 tokens agreed with the module 04/01 cache with a maximum absolute difference of 1.19e-07, confirming that the tokenization and the vocabulary order are right.

  • Results (13 classes, 13 donors; the PCA and frozen-embedding rows use a logistic head, and the fine-tuning row uses a linear head trained together with the backbone):

  • Controls: The positive control (the pretraining effect) covered only the first 5 donors. The pooled macro-F1 of the fine-tuning is 0.702, that of fine-tuning in the same way from random initialization is 0.269, the mean balanced-accuracy Δ is +0.392 and 5/5 are positive (the pre-specified rule was met). Since there are only two folds and the shuffled-label model is pulled toward the training marginal distribution, this baseline is an approximation. It does not contradict there being no signal, but it is not a tight test (it is far from PCA 0.79 and fine-tuning 0.76).

  • How to read it: Fine-tuning fills much of the gap of the V1 frozen embeddings. On the same 512 tokens it went from 0.673 to 0.779, higher even than the 0.724 of the 2,048-token frozen one. But it does not reach PCA in this setting (−0.077, lower in 12 of 13 donors). Truncating the input to 512 alone drops the frozen embedding from 0.724 to 0.673 (−0.051), so the possibility that the 512-token truncation lowered the ceiling of fine-tuning could not be separated in this run.

  • Cautions and unverified: ① Only V1-10M was used, there is 1 seed, and the hyperparameters were fixed and not tuned (the README strongly recommends tuning). Tuning may improve fine-tuning, so this value is a result “in this fixed setting”. ② V2-104M could not be fine-tuned in this section (it was run in C③-V2). ③ The positive and negative controls were run on only some of the folds (5 and 2). ④ The training loss fell to about 0.35 at epoch 2 (there is no validation fold, so overfitting was not measured). ⑤ The mean-pooling head differs from the official classification head. ⑥ 92% of the cells are truncated at 512 tokens. ⑦ PCA is a transductive setting (the same conclusion as the strict fit). ⑧ There are 13 donors and one dataset.

  • Reproduction and review history: 20 folds (13 + 7 controls) were run once (5,454 seconds in total; about 216 seconds per fold when alone, and 300–420 seconds in the intervals run concurrently with other jobs). With the final script that reflects the cross-review, the report was rebuilt from the cached fold results (55 seconds) and the numbers were the same. What was incorporated is as follows. The “500 tokens” notation in an output label was corrected to match the code (MAX_LEN = 512) (the typo remains in the log of the 1st run). The resume cache was moved to a directory of the settings·data fingerprint (after confirming that the settings, data hash, revision and package versions of the 1st run matched the new fingerprint, the files were moved). A PRIMARY marking error was fixed. The strict per-fold PCA sensitivity was added (post-hoc analysis).

C③-V2 — Fine-tuning Geneformer V2-104M (track C, Colab A100, 2026-11-10)¶

On the Mac (MPS) it is about 8 seconds/step, so only the training was run on a Colab A100 (user approval: A100, fp32), and the baselines and the report were made on the Mac. Script: h2_C_geneformer_v2_finetune.py (stages check/bench/train/report).

  • Setup (fixed): The same data, split, hyperparameters and decision rule as C③, and the model (and what comes with it) and the pooling differ. The model is Geneformer V2-104M (the same revision 1f7fbae4…). The author fixed the setup having already seen the results of C③ (V1 fine-tuning −0.077), V2 frozen (4,096 tokens 0.838) and PCA (0.856), and fixed it before seeing the V2 fine-tuning results. What was seen before the main run was the A100 benchmark output (the step time and memory, and the training loss of the first few dozen steps of one fold), not an evaluation metric.

  • Data inspection: The token sha256 is the same on the Mac and the VM (4c43f5b3abea…; the input h5ad sha256 6ed51086… was also compared after uploading). The first 100 cells of the newly computed 4,096-token V2 frozen <cls> on the Mac agree with the module 04/01 cache with a maximum absolute difference of 0.00 (the check stage).

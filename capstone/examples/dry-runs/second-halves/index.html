트랙 A~D의 “질문의 나머지 절반” 시험 실행 기록 (2026-11-09)

시험 실행 기록은 트랙마다 질문 하나(MVP)만 실행했다. 이 문서는 캡스톤 README §2 표의 질문 중 그때 실행하지 못한 쪽을 같은 방식으로 실행한 기록이다. 템플릿 구조는 사전 등록, 출처, 데이터 점검, 분할·누출, baseline, 평가, 대조, 민감도 순이다.

이 기록의 성격

  • 학습자 파일럿이 아니다. 과정을 만든 쪽이 직접 한 번씩 실행했다. 소요 시간은 이 Mac(MPS)에서 잰 한 번의 값이다.

  • 실제 사전 등록이 아니다. 각 스크립트 머리에 작성자가 이미 본 결과(모듈 노트북의 관련 결과)를 적었다. 결정 규칙과 임계값은 실행 전에 코드에 고정했지만, 결과를 보기 전에 정했음을 증명할 수는 없다.

  • 새로 내려받은 것은 D③의 CSV 3개(승인 후, 합 3.95 MB), C②의 H5AD 1개(승인 후, 150 MB), C④의 scGPT 소스 .py 26개(273,078 B)와 whole-human 체크포인트 3개 파일(약 207 MB)뿐이다. 마지막 둘도 승인 후에 받았다. 나머지는 캐시만 썼다. 임베딩과 미세조정 fold 결과는 .cache/capstone_runs/에 새로 저장했고 git에서는 제외했다. 설치(pip install)는 하지 않았다.

  • Codex·agy 교차 리뷰를 받았다(맨 아래 “교차 리뷰” 절).

  • 결과를 "ESM-2/NT/ChemBERTa/Geneformer는 …하다"로 일반화하지 않는다. 각 행은 데이터, 모델, head를 고정한 한 번의 비교다.

실행: 저장소 루트에서 HF_HOME=$PWD/.cache/hf HF_HUB_OFFLINE=1 .venv/bin/python -I <스크립트>. 실행 기록(provenance.json)은 .cache/capstone_runs/<RUN_NAME>/에 쓴다.

C① — 라벨 입도와 zero-shot 순위 (트랙 C)¶

  • 설정(고정): Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명, leave-one-donor-out이다. 표현은 전부 동결하고 head는 코사인 kNN(k = 15, 모듈 04/02와 같음)이다. 표현은 5종이다: PCA(HVG, 50), Geneformer V2 <cls> L-2, V2 평균 L-2, V1 평균 L-2, V1 무작위 초기화. 입도는 3종이다: 거친 13종, cellxgene cell_type 19종, 세부 20종. 세부는 트랙 C 스크립트와 같은 재현 절차로 복원했고 assert를 통과했다. 지표는 풀링 macro-F1이고, 구간은 기증자 부트스트랩 1,000회로 구했다(모든 비교에 같은 재표본 인덱스).

  • 주 질문의 정의: 어떤 표현 쌍에서 거친 라벨과 세부 라벨의 Δ 부호가 반대이고 둘 다 구간이 0을 제외하면 “순위가 바뀐다”(지지)고 본다.

C④ — scGPT zero-shot 임베딩 vs PCA·Geneformer (트랙 C)¶

  • 설정(고정): C③과 같은 데이터(Wilk 2020 PBMC 하위표본 10,400세포, 기증자 13명 leave-one-donor-out, 거친 라벨 13종)이고 트랙 C MVP·C①과 같은 분할이다. 주 비교는 scGPT(whole-human) <cls> 임베딩 + 로지스틱 head(C = 1)와 PCA(HVG, 50) + 같은 head의 비교다. 결정 규칙은 트랙 C MVP와 같다(기증자별 균형정확도 Δ 평균 ≥ 0.02, Δ > 0인 기증자 ≥ 9/13, 풀링 macro-F1 Δ의 기증자 부트스트랩 구간 하한 > 0). 작성자는 같은 데이터에서 Geneformer V2 < PCA를 이미 보았고 scGPT 결과는 보기 전에 정했다.

  • 주의·미확인: ① 입력 구성이 공식 embed_data와 완전히 같지는 않다(위 “공식과 다른 점”; 자체 루프). ② 체크포인트 args.json에는 no_cls = true, no_cce = true, MVC = true가 기록되어 있다. 이름으로는 분류·대조 손실을 끄고 GEPC(MVC) 디코더를 켠다는 뜻으로 보이지만, 실제 사전학습에서 이 플래그가 그렇게 쓰였는지는 확인하지 못했다⚠️. cell_emb_style은 기록되어 있지 않아 <cls> 위치가 사전학습에서 세포 표현으로 쓰였는지도 확인하지 못했다⚠️. 2026-11-09에 재확인해 좁혀진 것은 이렇다. 가져다 둔 소스(model.py)에서 MVC가 켜져 있으면 GEPC 디코더의 입력이 cell_emb이고, cell_emb_style의 기본값 "cls"에서는 그것이 <cls> 위치 출력이다. 그러나 이 체크포인트가 그 기본값으로 학습됐다는 기록은 없다. scGPT 저장소의 zero-shot 튜토리얼 README는 원래 사전학습을 "순수 데이터 기반 자기지도(유전자 발현 재구성)"로 서술하고 있어 no_cls/no_cce 기록과 모순되지 않는다. 그래서 <cls>와 유전자 평균 풀링을 둘 다 냈고(결론은 같다), <cls> 결과를 "<cls>가 사전학습된 세포 표현"으로 해석하지 않는다. ③ 무작위 유전자 표본을 뽑은 세포 22%는 시드를 고정한 표본이라, 다른 시드에서의 변화는 재지 않았다. ④ 사전학습 코퍼스와의 겹침은 확인하지 못했다⚠️. 확인한 것은 다음과 같다. scGPT whole-human은 README에 "정상 인간 세포 3,300만 개"로만 적혀 있고 데이터셋 목록은 찾지 못했다. 같은 연구(Wilk 2020)의 데이터셋이 CELLxGENE Discover에 2020-09-28부터 공개되어 있고(44,721세포, COVID-19와 normal 라벨 둘 다 포함; 다른 컬렉션에 비-primary 사본도 있다) 이 데이터는 COVID-19 환자 PBMC를 포함한다. 건강 기증자의 세포가 코퍼스에 있었을 가능성은 있으나 확인하지 못했다. ⑤ 저장소가 zero-shot 세포 임베딩용으로 따로 제공하는 체크포인트 scGPT_CP는 쓰지 않았다. 이것은 whole-human에 Tabula Sapiens 세포 유형 라벨 지도 학습을 더한 것이고 README는 원본과 같거나 더 낫다고 적고 있다. 이 실행은 README의 기본 추천 모델(whole-human)을 썼다. scGPT_CP는 세포 유형 라벨로 지도된 모델이라 이 비교와는 성격이 다르고, 쓰려면 추가 다운로드(승인)와 설계가 필요하다. ⑥ 동결 임베딩 비교다. 미세조정한 scGPT에 대해서는 말하지 않는다. ⑦ PCA는 모든 기증자로 적합한 transductive 설정이다(위 ③에서 엄격 적합과 거의 같음을 확인했다). ⑧ 어휘와 연결되지 않은 유전자 17%(카운트 1.0%)는 입력에서 빠졌다. ⑨ 기증자는 13명, 데이터셋은 하나, 로지스틱 head도 하나다.

  • 재현·검토 이력: 전체를 두 번 실행했고 두 번의 임베딩이 비트 단위로 같았다(최대 절대차 0; MPS, 같은 시드, 같은 순서). 2차 실행은 교차 리뷰를 반영한 스크립트로 했다(가중치 전수 점검, 입력 데이터 해시를 넣은 캐시 키, L2 순서와 엄격 PCA 민감도 추가). 이 두 민감도는 1차 결과를 본 뒤에 추가한 사후 분석이다. 주 결과 수치는 1차와 같았다.

  • 계산(Mac MPS, C③ 미세조정과 동시 실행이라 단독 시간이 아님): 임베딩은 whole-human 564초 + 무작위 초기화 553초(스모크: 128세포 5초, 전체 단독 약 7분으로 환산)였고 전체는 1,507초였다.

D② — 표기 증강 vs 정규화 (트랙 D, 모듈 05 과제 2)¶

  • 설정(고정): Lipophilicity 4,200, scaffold 분할(노트북 05/01과 같은 함수·시드) 5-fold × 3회, 동결 ChemBERTa-77M-MLM(평균 풀링, 마지막 층) + ridge다. 비교 변형은 canon(정규화 SMILES만 학습), avgK(학습 분자의 무작위 표기 K개 임베딩을 평균), rowsK(K개를 행으로 증강)이고 K = 1/5/20이다. test 입력 조건은 3종이다: 정규화, 분자당 무작위 표기 1개(rand1), 무작위 표기 5개 평균(tta5). (c) "추론 때 항상 정규화"는 canon 학습 + 정규화 test다. 학습과 test의 무작위 표기는 시드 집합이 서로 다르다(학습 20벌, test 5벌).

  • ridge: 알파는 변형이 학습하는 입력과 같은 분포(정규화, 증강 행, 평균 행)에서 분자(scaffold) 단위 안쪽 3-fold로 고른다(증강 행은 한 분자가 여러 행이라 RidgeCV의 leave-one-out은 누출이다). canon 변형의 결과는 노트북 05/01과 같다(반복 0: 정규화 0.863, 무작위 표기 1.455 vs 노트북 0.863 / 1.448).

B① — NT probe의 이득이 의존하는 것 (트랙 B)¶

  • 설정(고정): 모듈 03/01의 프로모터 분류다(promoter_tata train 5,062 / test 212, promoter_no_tata train 6,000(30,000 중 무작위) / test 1,372; test는 chr20·chr21이고 train과 염색체가 겹치지 않음). NT-500M 평균 임베딩(특수 토큰과 패딩 제외)을 층 0~24의 짝수 층 13개에서 뽑아 표준화 + 로지스틱 probe에 넣고, C는 train 안의 염색체 단위 3-fold(AUROC)로 선택한다. baseline은 k-mer 빈도(k = 3~7, 차원 64~16,384)다. 학습 크기는 n = 500~6,000이다.

  • 결정 규칙: train CV로 고른 층 − 6-mer의 ΔAUROC ≥ 0.01이고 test 재표본 95% 구간 하한 > 0이며, 두 과제 모두일 때 '지지’다.

  • 주 비교: promoter_tata는 층 12에서 Δ +0.001 [−0.030, +0.029](NT 0.925 vs 0.925)로 지지되지 않는다. promoter_no_tata는 층 16에서 Δ +0.010 [+0.004, +0.017](0.947 vs 0.936)로 지지다. 전체로는 지지되지 않는다. 모듈 03/01의 값(tata 층 12 +0.001, no_tata 층 18 +0.010 [+0.003, +0.017])과 일치한다.

  • 의존성:

    • 층: Δ(고정 층 − 6-mer)는 tata에서 층 0~8(−0.033~−0.022), no_tata에서 층 0~6(−0.022~−0.002)까지 음수이고, 층 10부터는 둘 다 양수가 된다. 층별 Δ 범위는 tata가 −0.033~+0.022, no_tata가 −0.022~+0.012다. 선택 방식에 따라 보면, tata는 CV가 층 12(Δ +0.001)를 골랐지만 마지막 층 24는 +0.021, test 오라클 층 22는 +0.022다. no_tata는 CV 층 16이 +0.010, 마지막 층이 +0.008, 오라클 층 14가 +0.012다. tata에서 구간이 양수 쪽으로 0을 제외한 층은 없다(층 2·4·6은 음수 쪽으로 제외; test 212개).

    • baseline k: no_tata의 NT 이득은 k = 3에서 +0.024, 4에서 +0.017, 5에서 +0.014, 6과 7에서 +0.010으로 줄지만 모든 k에서 지지된다. tata는 k = 3(+0.037 [+0.004, +0.072])에서만 지지되고 k = 4(+0.010)부터 구간이 0을 포함하며 k = 7에서 −0.011이다. baseline의 크기가 이득의 크기를 정한다.

    • 학습 크기 n(층 후보 {6, 12, 18, 24}, 같은 n의 6-mer와 비교): no_tata의 Δ는 n = 500 / 1,000 / 2,000 / 4,000 / 6,000에서 +0.015 / +0.013 / +0.013 / +0.018 / +0.010이며 뚜렷한 추세가 없다. tata는 −0.012~+0.010으로 어디서도 구간이 0을 제외하지 못했다(tata의 train은 5,062개뿐이라 n = 6,000 행은 실제로 5,062개 전부다). 경계 주의: n = 6,000에서 층 후보를 4개로 제한하면 CV가 층 18을 골라 Δ가 +0.010으로 표시되지만 반올림 전 값이 임계값(0.01) 아래라 '지지되지 않음’이다. 반면 13개 층에서는 층 16의 Δ가 +0.010(임계값 이상)이라 '지지’였다. 같은 과제와 같은 데이터의 비교가 임계값 근처에서 반올림 한 자리 미만의 차이로 갈린다(정확한 값은 기록하지 않았다).

  • 주의: test 염색체가 2개라 구간은 test 서열 재표본이며(인접 창의 상관을 무시해 낙관적), CV로 고른 층을 고정한 채 재표본하므로 층 선택의 변동은 구간에 들어 있지 않다. no_tata는 train 30,000 중 6,000만 썼다. 라운드 7 — ⚠️ 항목 갱신(C②·C④ 문장; Codex·agy 각 일부): 웹 페이지(scGPT README와 zero-shot 튜토리얼 README, Hugging Face Geneformer 모델·데이터셋 카드, CELLxGENE Census 중복 세포 튜토리얼, Discover 컬렉션 목록)를 다시 읽고 고친 문장을 검토받았다. 리뷰어는 외부 페이지를 열 수 없어 서술은 독립적으로 검증되지 않았고, 내부 일관성과 단정 정도만 점검되었다. 반영하지 않은 것은 다음과 같다. agy가 is_primary_data 설명을 “대표 사본 대 비대표 사본” 식으로 일반화하라고 했으나, 내가 읽은 공식 문서 문장은 "다른 데이터셋과 중복인 세포가 False"까지이고 그 이상(대표 사본 지정 등)은 읽지 않아 현재 서술을 유지했다.

C③-V2 교차 리뷰 (2026-11-10)¶

라운드 8 — 스크립트, 보고 로그, 학습 로그, 문서(Codex 10건, agy 약 17건; 지적마다 코드와 로그로 확인). 두 리뷰어 모두 결과 표, 주 비교의 구간·승수·판정, 기증자별 값, 대조 수치가 로그와 일치하고, 미세조정 분할이 held-out 기증자를 제외하며 라벨 섞기가 훈련 라벨만 바꾼다는 점을 확인했다. 반영한 것은 다음과 같다. ① 무작위 초기화의 손실 "2.23 → 1.77"이 5개 fold 중 C5 하나의 값이었다(Codex·agy; 로그로 확인). 범위와 평균으로 고치고 "학습되지 않았다"는 서술을 낮췄다. ② 절단 손실을 "메우고도 남았다"는 인과 서술(Codex·agy)을 고쳤다. 미세조정은 마지막 층, 동결은 L-2 층 + 정규화 + 로지스틱이라는 차이(코드로 확인)를 적고 관찰된 차이로만 서술했다. ③ “모델과 풀링만 다르다”(agy)에는 사전, 특수 토큰, 유전자 수 510도 다르다고 명시했다. ④ check가 앞 100개 세포만 대조한다는 점(Codex; 코드로 확인)을 문장에 반영했다. ⑤ 벤치마크가 훈련 손실도 출력한다는 점(Codex)을 사전 공개 문장에 반영했다. ⑥ “PCA와 비슷하거나 약간 위”(agy)를 "구별되지 않는 수준"으로 고쳤다. ⑦ 음성 대조 C1이 기준선보다 0.055 높음(Codex), 보고 시간 61초 vs 59초(둘 다; 두 번 실행한 값), 7,087초에 임베딩 56초 포함(Codex), 참고 비교의 생략된 구간(agy)을 수정했다. ⑧ 캐시 지문이 스크립트, 패키지, 층을 묶지 않음(Codex·agy)과 로그에 없는 운영 수치(둘 다)는 주의 ⑨·⑩으로 공개했다. ⑨ decide가 구간이 없으면 통과한다는 점(Codex)은, 호출이 항상 구간을 넘기지만 ci is not None and로 고치고 보고서를 다시 만들어 수치가 같음을 확인했다. 반영하지 않은 것은 다음과 같다. ⑩ A100의 fp32가 실제로는 TF32라는 지적(agy): PyTorch 문서상 torch.backends.cuda.matmul.allow_tf32의 기본값은 1.12부터 False이고 스크립트는 이를 바꾸지 않으므로 주장대로라고 볼 근거가 없다. 다만 VM에서 값을 직접 읽지 않았으므로 주의 ⑧에 "확인하지 않음"으로 적었다. ⑪ PCA 기준선의 transductive 전처리(둘 다): 이미 엄격 fold별 민감도와 주의 ⑥으로 다뤘다. ⑫ 엄격 PCA의 ddof, 0-합 세포, 빈 토큰 세포(agy, 낮음): 해당 사례가 이 데이터에 없고 C②③④와 같은 코드라 그대로 두었다. agy의 첫 항목(평가 예측 순서 오류)은 리뷰어가 스스로 철회했다.

치트시트 04 — 계산량·메모리·환경

모듈 06(노트북 03)과 SETUP.md에서 측정하거나 확인한 것과, 측정하지 않고 공식(근사)으로 어림한 것을 구분해 모았다. 표기: 측정 = 이 저장소에서 실행한 값, 공식 = 계산식이며 활성값 등을 뺀 어림, † = 확인하지 못한 서술. python 블록은 저장소 .venv에서 실행해 확인했다(2026-11-06).

def budget_gb(n_params, mode="full_fp32", n_trainable=None):
    """활성값을 뺀 메모리 어림(GB, 1 GB = 1e9 바이트). 측정값이 아니라 공식이다."""
    if mode == "infer_fp32": b = 4 * n_params
    elif mode == "infer_bf16": b = 2 * n_params
    elif mode == "full_fp32": b = 16 * n_params
    elif mode in ("lora_fp32", "lora_bf16"):
        frozen = (4 if mode == "lora_fp32" else 2) * (n_params - n_trainable)
        b = frozen + 16 * n_trainable
    else: raise ValueError(mode)
    return b / 1e9

assert abs(budget_gb(650e6, "full_fp32") - 10.4) < 0.01                   # 모듈 06 §5: 650M 전체 파인튜닝 ≈ 10.4 GB
assert abs(budget_gb(650e6, "lora_fp32", 1.35e6) - 2.6) < 0.1             # LoRA(q,v r=8) ≈ 2.6 GB
assert abs(budget_gb(650e6, "lora_bf16", 1.35e6) - 1.3) < 0.1             # 동결 가중치 bf16 ≈ 1.3 GB
print({m: round(budget_gb(650e6, m, 1.35e6), 2) for m in ["infer_fp32", "infer_bf16", "full_fp32", "lora_fp32", "lora_bf16"]})

  • 활성값은 배치·서열 길이·층 수에 따라 크게 달라져 위 공식에 없다. 작은 모델·짧은 서열에서도 설정에 따라 달라지므로 해당 설정에서 측정하고, 긴 서열에서는 지배적일 수 있다 (아래 §3).

  • 8M·35M 모델에서는 방법 간 차이가 0.1~0.5 GB라 장비 차이에 묻힌다 (모듈 06).

2. 연산량 어림¶

  • 트랜스포머 학습 연산량 C≈6NDC \approx 6NDC≈6ND (N 매개변수, D 토큰)†, 순전파 ≈2ND\approx 2ND≈2ND†. 모듈 06은 이 식과 Mac MPS 측정 처리량으로 시간을 어림했다.

  • 시간은 연산량을 같은 장비·같은 구현에서 측정한 처리량(FLOP/s 또는 token/s)으로 나눠 어림하며, 단위를 맞춘다. 다른 장비로 옮길 때는 다시 측정한다. 모듈 04에서 Colab T4가 Mac MPS보다 빠르다고 가정할 수 없음을 측정했다. Geneformer V2-104M 추론(fp32)이 T4 788초, Mac 673초였고, CPU 학습인 scVI는 Colab 2코어에서 757초, Mac에서 134초였다. 반대로 모듈 06 노트북 01(LoRA·전체 파인튜닝, GPU 중심)은 T4가 721초로 Mac MPS의 약 1,156초보다 빨랐고, CPU 위주인 모듈 05 노트북 01(sklearn 교차검증)은 Colab(vCPU 2개)에서 약 60분으로 Mac의 약 10분보다 훨씬 느렸다. 단일 실행이며 반복 측정이 아니다.

3. 측정값 (Mac MPS, ESM-2 35M, 배치 4, forward+backward 중앙값 3회)¶

메모리는 MPS 드라이버 할당량이라 peak가 아닌 대리 지표다. 같은 설정의 시간이 실행마다 약 10% 흔들렸다.

10241.00 s · 7.84 GB0.98 s · 7.85 GB1.11 s · 7.90 GB1.28 s · 2.48 GB

(모듈 06 README §5-C의 표와 같다.) 읽는 법:

  • 서열 길이가 128에서 1024로 길어질 때 메모리는 약 12배 늘었다. 활성값이 지배한다. 길이 1024에서 체크포인팅은 메모리를 −68%, 시간을 +31% 바꿨다.

  • 이 Mac에서 sdpa와 eager의 대리 메모리는 같았다. MPS에는 FlashAttention 커널이 없다†. Colab T4(CUDA)에서는 달랐다. 같은 설정(35M, 배치 4, 길이 1024)에서 최대 할당 메모리가 eager fp32 7.34 GB, sdpa fp32 2.58 GB, 체크포인팅까지 적용하면 0.61 GB였다(max_memory_allocated라 MPS의 드라이버 대리 지표와 다른 지표다. 모듈 06 README §8).

  • bf16 autocast는 이 장비에서 시간 이득이 없었다 (+9~20%).

import gc
import numpy as np, torch

def mps_mem_gb():
    """MPS 드라이버 할당량(GB). peak가 아니라 캐시를 포함한 대리 지표."""
    if not torch.backends.mps.is_available():
        return float("nan")
    return torch.mps.driver_allocated_memory() / 1e9

gc.collect()
if torch.backends.mps.is_available():
    torch.mps.empty_cache()             # 측정 전에 정리하지 않으면 직전 작업의 버퍼가 섞인다 (모듈 06에서 겪음)
before = mps_mem_gb()
x = torch.zeros(256, 1024, 1024, device="mps" if torch.backends.mps.is_available() else "cpu")   # 1 GiB(=1.07 GB, 십진 GB 기준) fp32
after = mps_mem_gb()
print("MPS 대리 지표 변화(GB):", None if np.isnan(after) else round(after - before, 2))
del x; gc.collect()
if torch.backends.mps.is_available():
    torch.mps.empty_cache()

5. 장비 특이점 (겪은 것)¶

증상원인/해결
torchrun --standalone이 300초 뒤 타임아웃 (macOS)호스트 이름이 1.0.0.127.in-addr.arpa로 풀린다. --local-addr=127.0.0.1을 준다
메모리 측정이 직전 실행의 영향을 받음gc.collect() + torch.mps.empty_cache() 후 측정
시간 측정이 흔들림다른 GPU/CPU 작업과 겹치지 않게 단독 실행, 중앙값 3회 이상
짧은 데이터에서 DDP가 2 step 만에 끝남에폭 루프와 sampler.set_epoch(epoch) 사용
패키지 버전이 달라 결과가 다름requirements/base.lock.txt로 재현, 모델은 리비전 고정
큰 파일이 git에 들어감.cache/(가중치·데이터)는 .gitignore에 있다. 커밋 전 git status로 확인한다
Colab에서 peft 임포트가 Found an incompatible version of torchao로 실패이미지의 torchao 0.10.0이 peft 0.21.2(torchao 0.16 이상 요구)와 충돌한다. 노트북이 쓰지 않으므로 pip uninstall -y torchao 후 커널을 다시 시작한다
GPU 1개에서 torchrun --nproc_per_node=2 DDP가 실패rank 1이 cuda:1을 열지 못한다. CPU(gloo)로 확인하려면 하위 프로세스에 CUDA_VISIBLE_DEVICES=""를 설정한다 (모듈 06 노트북 03)
Colab에서 모델 로드 중 커널이 갑자기 죽음 (ESMFold, RAM 12 GB)가중치가 fp32로 CPU RAM에 먼저 올라가 약 14 GB를 요구해 cgroup OOM이 난다. 3회 중 2회 실패했다. from_pretrained(..., device_map={"": 0})로 GPU에 바로 올리면 CPU 메모리는 1 GB 미만(파일 캐시 제외)이고 GPU 순간 최대는 약 14.1 GB다
colab exec 중 커널이 죽었는데 CLI가 끝나지 않음--timeout이 연결 끊김에는 듣지 않았다(4.6시간 대기, 약 5 CU 소모). 셸의 timeout 600 colab exec ...로 감싸고 끝나면 colab stop을 실행한다

6. 실행 전 체크¶

  • 필요한 다운로드(파일·출처·크기)를 적고 승인을 받았다

  • 메모리 공식으로 어림하고, 활성값(서열 길이·배치)을 따로 점검했다

  • 시간·메모리를 보고할 때 대리 지표임과 장비를 적었다

  • 실행하지 못한 환경(클러스터, 다른 GPU)을 "미검증"으로 적었다
